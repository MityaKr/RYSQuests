A · Откуда идея

Что раздражает в FTB Quests при 2000+ квестах

Редактор только в игре

Каждый квест руками: клик, окно, поля. Для больших книг авторы пишут генераторы, а SNBT-формат с числовыми id не для этого создавался.

Паутина зависимостей

Линии между квестами накладываются друг на друга, раскладка ручная, при добавлении квеста сдвигать приходится всё.

Тормоза на больших главах

Открытие книги и переключение глав подвисают: рендер всех квестов разом, синхронизация прогресса целиком.

Хрупкий прогресс

Переименовал или пересоздал квест, id поменялся, у игроков прогресс пропал. Файл соответствия id приходится беречь как зеницу ока.

Квест и рецепт живут отдельно

Чтобы понять, как сделать предмет из задачи, игрок закрывает книгу и идёт в JEI. Назад возвращается по памяти.

Автор слепой

Нет данных, где игроки застревают, какие квесты никто не делает, сколько времени занимает глава. Узнаёшь из Discord.

B · Принципы

Те же пять правил, что у RYScope, плюс одно

Данные сначала

Книга это JSON-файлы с человекочитаемыми ключами в датапаке. Редактор в игре пишет те же файлы. Git, генераторы, ревью диффов работают из коробки.

Стабильные id

Квест идентифицируется строковым ключом, который задаёт автор. Переименование идёт через файл миграций, прогресс игроков не теряется никогда.

Ноль фризов

Карта главы рендерится виртуально, прогресс синхронизируется диффами, раскладка кэшируется. Книга из 5000 квестов открывается так же быстро, как из 50.

Одна семья с RYScope

Общие темы, токены, виджеты и HUD-стикеры. Рецепт в квесте показывается прямо в карточке, квест в RYScope показывается на замке рецепта. Каждый мод работает и без другого.

Автор на равных с игроком

Dev-режим, отчёты, аналитика, горячая перезагрузка. Книга собирается и проверяется как код.

Совместимость входа

Импорт из FTB Quests вместе с прогрессом игроков. Без этого ни одна живая сборка не перейдёт.

C · Внешний вид

Темы те же, видов книги четыре

Темы Slate, Vanilla Refined, Glass и Paper общие с RYScope: один формат JSON + текстуры, одна настройка переключает оба мода. Книга показывается четырьмя видами, игрок выбирает любой, автор задаёт вид по умолчанию для главы.

Фича 01

Карта главы с автораскладкой

Раскладка считается автоматически (слоёный граф слева направо, как в Factorio-калькуляторах), автор может зафиксировать отдельные узлы руками. Завершённые ветки сворачиваются в один узел, линии зависимостей ведут только к видимым узлам, подсветка пути от выбранного квеста к корню. Квесты группируются в рамки «подглав» с заголовком.

Фича 07

Редактор и файловый формат

Редактор в игре: перетаскивание, мультивыделение, копирование квестов и целых подглав, зависимости тянутся мышью, правка текста с предпросмотром. Но он только пишет файлы: один JSON на квест (или на подглаву), человекочитаемые ключи, порядок полей стабилен, никаких числовых id. Это значит: git показывает осмысленные диффы, генератор на Python пишет те же файлы, горячая перезагрузка подхватывает изменения и подсвечивает на карте, что изменилось.

// data/mypack/rysquests/chapters/02_power/electric_mechanism.json
{ "id": "mypack:power/electric_mechanism",
  "title": "quest.mypack.power.electric_mechanism.title",     // lang-ключ, можно и literal
  "icon": "kubejs:electric_mechanism",
  "requires": ["mypack:power/wires", "mypack:power/dynamo"],
  "requires_mode": "all",
  "tasks": [
    { "type": "item", "item": "#c:plates/copper", "count": 16, "mode": "consume" },
    { "type": "advancement", "id": "mypack:electrician" },
    { "type": "item", "item": "kubejs:electric_mechanism", "count": 3, "mode": "observe" } ],
  "rewards": [
    { "type": "choice", "of": [ {"type":"item","item":"minecraft:gold_ingot","count":8},
                                {"type":"item","item":"mekanism:basic_control_circuit","count":2} ] },
    { "type": "xp", "levels": 2 },
    { "type": "stage", "stage": "2" } ],
  "layout": { "pin": false },        // авто-раскладка; {"x":12,"y":4} фиксирует
  "text": "quest.mypack.power.electric_mechanism.text" }

Один файл на квест удобен для генераторов и git. Для маленьких книг разрешён и один файл на главу: формат тот же, просто массив.

Фича 08

Стабильные id и миграции

Прогресс игрока хранится по строковому id квеста. Переименование делается записью в migrations.json, удаление квеста не трогает чужие записи. Перед релизом команда /rysquests migrate --dry-run показывает, что произойдёт с прогрессом: сколько записей переедет, сколько останется без квеста (и будет сохранено как «архив», не потеряно). Сервер применяет миграции при загрузке один раз и логирует.

$ /rysquests migrate --dry-run rename mypack:power/el_mech → mypack:power/electric_mechanism (184 игрока) merge mypack:power/wires_a + wires_b → mypack:power/wires (91 игрок, прогресс = max) remove mypack:power/old_test (3 игрока → архив) ok 2297 квестов без изменений Применить: /rysquests migrate --apply

Фича 09

Команды и режимы прогресса

Три режима на уровне книги с переопределением на главе или квесте: индивидуальный, командный (общий прогресс и общие награды или награда каждому), серверный (один прогресс на весь мир, для кооп-серверов). Команды без отдельного мода: создание, приглашение, передача лидера, гость (видит прогресс, не влияет). Прогресс синхронизируется диффами, уведомления о действиях команды в «Что дальше».

Фича 10

Фича 11

Текст, локализация, ссылки

Все строки через lang-ключи с первого дня, редактор в игре пишет в lang-файл текущего языка. Разметка текста общая с RYScope: [[item:…]] с иконкой и подсказкой, [[quest:…]] открывает квест, [[recipe:…]] разворачивает рецепт, [[guide:…]] и [[ponder:…]] ведут в GuideME, Patchouli, Ponder. Картинки из ресурспака, предупреждения, спойлеры. Для гайд-квестов есть тип «страница»: только текст, без задач, засчитывается прочтением.

Фича 12

Импорт из FTB Quests

Команда импорта читает config/ftbquests (SNBT): главы, квесты, задачи, награды, раскладку, зависимости, тексты, и пишет JSON RYSQuests с ключами из названий. Прогресс игроков из world/data/ftbquests переносится по сгенерированной таблице соответствия, которая сохраняется как первая миграция. Отчёт импорта перечисляет всё, что не удалось перенести один в один (экзотические типы задач, кастомные награды) и предлагает ближайший аналог.

D · Архитектура

Почему быстрее

1. Книга как неизменяемый граф
Загружается из датапака, индексируется по id, зависимостям и предметам задач. Пересборка по событию.
2. Раскладка в фоне и в кэше
Слоёный алгоритм считается в фоне, результат хранится на диске по хэшу главы.
3. Виртуальный рендер карты
Рисуются только узлы и линии в видимой области; завершённые ветки свёрнуты.
4. Прогресс диффами
Сервер шлёт только изменившиеся записи; при входе снимок сжат. Проверка задач по событиям, не по тикам.
5. Компактное хранение
Прогресс в бинарном формате с индексом по игроку и квесту; архив удалённых отдельно.
6. Общее ядро с RYScope
Темы, виджеты, стикеры, разметка текста в библиотеке RYScore; оба мода работают независимо.
главный поток: рендер, вводфон: раскладка, индекс, отчётысервер: события задач, диффы, миграции

E · API

Декларативно по умолчанию, Java и KubeJS для остального

// KubeJS
RYSQuestsEvents.task('mypack:looked_at_boiler', e => {
  e.title('Посмотреть на бойлер');
  e.check(player => player.rayTraceBlock(8).block.id == 'create:fluid_tank');
});
RYSQuestsEvents.completed(e => {            // реакция на выполнение
  if (e.quest == 'mypack:power/electric_mechanism') e.server.runCommand('...');
});
// Java
@RYSQuestsPlugin
public final class MyPlugin implements RYSQuestsPluginEntry {
  public void register(RYSQuestsRegistry r) {
    r.taskType("mymod:energy_stored", EnergyStoredTask.CODEC);
    r.rewardType("mymod:unlock_recipe", UnlockRecipeReward.CODEC);
    r.progressProvider(new MyStageBridge());        // стадии, Game Stages и т.п.
    r.recipeViewer(new RyscopeBridge());            // или JEI/EMI
  }
}

G · Дорожная карта

Порядок, при котором каждая стадия полезна сама по себе

0. Общая библиотека RYScore

Темы, виджеты, стикеры, разметка текста. Выделяется из RYScope, чтобы оба мода делили код. Тот же блокер со сборкой: maven NeoForge.

1. Ядро книги (MVP)

Формат JSON, загрузка из датапака, задачи предмет/продвижение/чекбокс, награды предмет/команда, карта с автораскладкой, список, прогресс с диффами, темы Slate и Vanilla. Импорт из FTB Quests. Цель: заменить FTB Quests в сборке без потерь.

2. Удобство игрока

«Что дальше», карточка с рецептом, HUD-трекер, лента, остальные типы задач и наград, команды.
