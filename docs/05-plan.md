# 05 · План работ

Один этап за раз. Этап закрыт, когда выполнены все критерии приёмки, тесты зелёные, `runClient` стартует без ошибок в логе, и автор подтвердил. После закрытия: коммит по просьбе автора, запись в `CHANGELOG.md`.

Оценки в «сессиях» условны: сессия это один рабочий блок режима кода с проверкой в игре.

## M0 · Среда и пустой мод (1 сессия)

Цель: проект собирается и запускается.

- Проверить доступ к `https://maven.neoforged.net/releases` и `https://maven.minecraftforge.net` (для ModDevGradle через Gradle plugin portal). Если недоступны, остановиться и обсудить с автором.
- `settings.gradle`, `build.gradle` с ModDevGradle (`net.neoforged.moddev`), `gradle.properties` с версиями (`minecraft_version=1.21.1`, `neo_version=21.1.x` — взять актуальную стабильную для 1.21.1 из maven), Java 21 toolchain.
- `neoforge.mods.toml`, класс мода `RYSQuests` с логом при загрузке, `Dist.CLIENT` обработчик.
- JUnit 5 подключён, один тест-заглушка.
- `.gitignore` (run/, build/, .gradle/, _stale/), `git init` по просьбе.
- Пример датапака из `examples/` подключается в `run/` как датапак мира (или через `data/` ресурсов мода на время разработки, флагом в конфиге dev).

Приёмка: `./gradlew build test` зелёный; `./gradlew runClient` открывает игру, в логе `RYSQuests loaded`.

## M1 · Модель данных и загрузчик (2 сессии)

- Записи `BookMeta`, `Chapter`, `Quest`, `TaskDef`/`RewardDef` базовые, `Layout`; кодеки.
- Реестры `TaskType`, `RewardType`; типы `item`, `checkbox`, `advancement` (задачи), `item`, `xp`, `command` (награды). Остальные типы в M5.
- `BookLoader` на `AddReloadListenerEvent`: parse → link → validate → `QuestBook` с индексами и хэшем.
- `BookValidator`: отсутствующие зависимости, циклы, дубли id, неизвестные предметы, lang без перевода (клиентская часть позже).
- Команды `/rysquests reload` (вызывает штатный reload), `/rysquests validate` (печатает отчёт в чат и в `logs/rysquests-validate.txt`).
- `BookSyncPayload` сжатый, разбиение на части; клиентский `ClientBook`.

Тесты: кодеки туда-обратно на `examples/`; валидатор ловит цикл и битую ссылку; хэш стабилен при перестановке полей.

Приёмка: пример книги грузится, `/rysquests validate` печатает «0 ошибок» на чистом примере и находит намеренно сломанный квест из `examples/broken/`.

## M2 · Прогресс и сдача (2–3 сессии)

- `ProgressStore` (SavedData), `ProgressService`: доступность (`requires_mode`), состояния, сдача `consume`, засчёт `observe` и `advancement`, выдача наград `item`/`xp`/`command`, `choice`.
- `TaskChecker`: редкий тик для `observe` с разносом по игрокам и кэшем хэша инвентаря; `AdvancementEarnEvent`.
- Payload'ы `ProgressSnapshot`, `ProgressDiff`, `SubmitTask`, `ClaimReward`, `Checkbox`.
- Режим `solo`. `TeamId` = UUID игрока.
- Команда `/rysquests progress <player> reset|complete <quest>` (права 2).
- Временная отладочная команда `/rysquests debug state <quest>` печатает состояние.

Тесты: `ProgressService` на фиктивной книге: цепочка требований, `any`/`n`, сдача без предметов отклоняется, диффы содержат только изменённое.

Приёмка: в тестовом мире квест из примера проходится командами и предметами, прогресс сохраняется между перезаходами, второй клиент (LAN) видит свой прогресс отдельно.

## M3 · Книга: Поток, карточка, стикеры, тема Slate (3 сессии)

- RYScore: `Theme`, `ThemeManager` (загрузка из ресурспака, одна тема `slate`), виджеты `Panel`, `Slot`, `ProgressBar`, `Button`, `Tabs`, `ScrollList`, `Tooltip`, `TextBlock` с разметкой (`[[item:]]`, `[[quest:]]`, жирный, предупреждение).
- `BookScreen` с шапкой, списком глав, видом **Поток**, карточкой квеста; открытие по K на текущем квесте.
- Сдача из карточки и по G; выбор награды; тост «Квест выполнен».
- `StickerBoard` и стикер квеста; закрепление по A и кнопкой; `PinQuestPayload`.
- Поиск Ctrl+F по названиям квестов текущей главы.
- Клиентский конфиг: тема, плотность, HUD в бою.

Тесты: парсер разметки (JUnit); остальное визуально.

Приёмка: игрок проходит пример от открытия книги до награды без консоли; стикер обновляется в реальном времени; экран масштабируется на GUI Scale 2–4 без наложений.

## M4 · Карта с автораскладкой, тема Vanilla (2 сессии)

- `LayeredLayout`, `LayoutCache`, рендер только видимого, свёрнутые выполненные ветки, группы, мини-карта, масштаб и перетаскивание, F фокус.
- Фиксация узлов через `layout.x/y`.
- Тема `vanilla` (бевели, серые панели, пиксельный стиль без скруглений) и переключение без перезапуска.
- `default_view` на главе и книге.

Тесты: раскладка детерминирована (одинаковый вход → одинаковый выход), слои соблюдают зависимости (зависимость левее), нет наложений узлов, 2000 узлов укладываются < 200 мс в фоне.

Приёмка: глава на 70 квестов читается без ручной правки; переключение глав без заметной паузы; обе темы корректны на всех экранах.

## M5 · Остальные типы, стадии, миграции, команды (2–3 сессии)

- Задачи `stat`, `visit`, `kill`, `fluid`; награды `loot_table`, `stage`; `repeatable`; `page`; `hidden`.
- `StageProvider` + встроенный на продвижениях; `stage_required`.
- `MigrationEngine`: rename/merge/remove/map, `applied_migrations`, бэкап, `/rysquests migrate --dry-run|--apply` с отчётом в чат и файл.
- Режимы `team` и `server`: минимальные команды `/rysquests team create|invite|join|leave`, прогресс на команду, `team_mode` наград.

Тесты: миграции на синтетическом прогрессе (rename переносит, merge берёт максимум, remove архивирует, повторное применение не дублирует); dry-run не меняет данные.

Приёмка: переименование квеста в датапаке + миграция сохраняет прогресс тестового игрока; два игрока в команде видят общий прогресс.

## M6 · Импорт из FTB Quests (2–3 сессии)

- Перед кодом: изучить формат по исходникам FTB Quests для 1.21.1 (см. `08-verify-first.md`): структура `config/ftbquests/quests/`, типы задач и наград, раскладка, зависимости, тексты, `world/data/ftbquests/` прогресс и команды.
- `/rysquests import ftbq [--dry-run]`: читает SNBT, строит JSON-файлы в `config/rysquests/import/<ns>/…` (не в датапак напрямую), генерирует lang из текстов, `migrations.json` с `map` числовых id, `import-report.md` со списком непереносимого и ближайших аналогов.
- Перенос прогресса игроков через `map`.

Тесты: импорт фикстуры из `examples/ftbq-fixture/` (небольшая книга FTB Quests, положить реальный экспорт из RepYS урезанный до 2 глав) даёт ожидаемые файлы.

Приёмка: книга RepYS (2300 квестов) импортируется за разумное время, отчёт перечисляет непереносимое, прогресс тестового игрока совпадает по выполненным квестам.

## M7 · Мост к вьюеру рецептов, разметка ссылок, dev-отчёты (2 сессии)

- `RecipeViewerBridge` + `JeiBridge` (JEI API в compileOnly; проверить актуальную версию для 1.21.1), кнопки «Рецепт» в карточке и клик по `[[item:]]`.
- `[[recipe:]]` предпросмотр, если мост умеет; иначе кнопка.
- Dev-отчёты: недостижимые квесты, задачи с предметами без рецепта (через мост или `RecipeManager`), строки без перевода, награды с несуществующими предметами; экспорт CSV в `logs/`.
- KubeJS-плагин: события `task`, `completed`, `reward` (если KubeJS в сборке; compileOnly).

Приёмка: клик по предмету задачи открывает JEI; отчёт по книге RepYS находит реальные проблемы (сверить с генератором автора).

## M8 · Полировка: «Что дальше», Список, Лента, производительность (2 сессии)

- Вид «Что дальше» (рекомендации, награды к получению, прогресс глав), «Список», «Лента» эпох (по `epoch` глав).
- Профилирование: открытие книги RepYS, переключение глав, размер пакета книги; оптимизация до целей из `00-vision.md`.
- `CHANGELOG.md`, `README` для CurseForge/Modrinth (черновик автору), иконка мода из `design/`.

Приёмка: цели производительности достигнуты на книге RepYS; автор прошёл главу I в тестовом мире и не нашёл блокеров.

## После MVP (не планировать сейчас)

Разделы книги и кастомные вкладки (Гайды, Атлас сборки, Атлас добычи, конструктор вкладок, Магазин, Достижения): этапы S1–S5, описаны в `09-sections.md`. В M1 из них закладывается только поле `section` у главы (по умолчанию `story`).

Редактор в игре; аналитика воронки; концепт «Компаньон» целиком; Fabric; темы Glass и Paper; экспорт книги в HTML.

## Правила между этапами

- Любая находка, меняющая архитектуру, оформляется ADR в `07-decisions.md` до реализации.
- Если этап не закрывается за две сессии против оценки, остановиться и обсудить срез.
- Пример датапака `examples/` обновляется вместе с форматом; это живая документация.
