# 02 · Формат данных

Всё в датапаке под `data/<namespace>/rysquests/`. Namespace обычно сборки (`repys`), не мода. Все id это `ResourceLocation`. Все строки, которые видит игрок, это lang-ключи либо literal; literal допускается и переводится через lang, если такой ключ есть.

## Книга: `book.json`

```json
{
  "progress_mode": "team",            // solo | team | server
  "default_view": "flow",             // home | flow | map | list
  "default_theme": "ryscore:slate",
  "title": "book.repys.title",
  "icon": "kubejs:brass_mechanism",
  "chapter_order": ["repys:01_create", "repys:02_power"],
  "hud": { "max_pinned": 3 },
  "sections": ["story", "guides", "repys:mining_atlas"], // рейка разделов, без поля её нет
  "epochs": [                         // эпохи, первая для "epoch": 1
    "book.repys.epoch.1",             // строка: только название
    { "title": "book.repys.epoch.2", "quest": "repys:a01_map/ii_industry" } // награда эпохи (0.2.7)
  ],
  "map_form": "auto",                 // auto | serpentine | spiral | generator | galaxy
  "published": true,                  // книга открыта игрокам
  "about": "repys:book"               // страницы «О книге» (0.2.7): id гайда или список страниц
}
```

Если `book.json` отсутствует, значения по умолчанию: `solo`, `flow`, `ryscore:slate`, `auto`, открыта.

Новые поля необязательные, старые книги читаются как раньше:

- `epochs`: названия эпох по порядку, ключ lang или литерал; глава с `epoch` за концом списка остаётся без названия. Эпоха, которую создал импорт FTB из группы глав, пишется объектом `{ "title": "...", "imported": true }`: это раздел книги, а не эпоха автора, и автовыбор формы её не считает (раздел 5 плана). Эпоха автора пишется строкой.
- `epochs[].quest` (0.2.7, ADR-60): квест, чьи награды становятся наградой эпохи. Эпоха с квестом пишется объектом `{ "title": "...", "quest": "<id квеста>" }` (вместе с `imported`, если оно есть). Такой квест не показывается карточкой своей главы: ни на карте, ни в списке, ни в поиске, ни в счёте главы. Глава, где кроме наград эпох живых квестов нет, уходит из сайдбара и с карты. Награду показывает плашка эпохи на карте и строка эпохи в сайдбаре (значок, пока награда ждёт), клик по плашке открывает карточку эпохи: текст квеста, награды, выбор, «Забрать награду». Награда ждёт и на «Сейчас» среди наград. Награда ждёт, когда у квеста выполнены зависимости, а из задач осталась только галочка: галочки ставятся при получении (действие `CLAIM_EPOCH` пакета `QuestActionPayload`, и «Забрать всё»). Задача другого вида держит эпоху закрытой, пока её не сделают. Под капотом это обычная выдача наград квеста: id, прогресс и отметки забранных наград те же, поэтому перенос квеста из главы в эпоху миграций не требует, а забранное раньше в главе остаётся забранным. Один квест можно назвать только у одной эпохи. Проверка книги: `epoch_unknown_quest` и `epoch_quest_twice` (ошибки), `epoch_quest_hidden` (черновик или архив, предупреждение).
- `about` (0.2.7, ADR-60): страницы «О книге». Строка это id гайда книги (`"repys:book"`): его страницы, отметки прочитанного и ссылки `[[guide:repys:book#coins]]` остаются гайдовыми, гайд по-прежнему есть и в библиотеке. Список это свои страницы в формате страниц гайда: `[ { "id": "welcome", "title": "<ключ>", "text": "<ключ>" } ]`, их прочитанное хранится под id `rysquests:about`, заголовок `rysquests.about.title` («О книге»). Название книги слева в шапке становится кнопкой со значком «i»: страницы открываются поверх вкладки, как настройки, «Назад: <вкладка>» возвращает; пока ни одна страница не прочитана, на значке книги горит точка. Блок «Гайд для начала» на «Сейчас» берёт эти страницы. Проверка книги: `about_unknown_guide` (ошибка), `about_empty` (предупреждение), `duplicate_guide_page` для своих страниц.
- `map_form`: форма карты. `auto` выбирает по правилу `MapForms`: большинство глав на карте с эпохой автора → `serpentine`; меньше 5 % связей между квестами ведут из главы в главу и глав 8 и больше → `galaxy`; иначе `generator`. `spiral` только по выбору автора.
- `published`: замок публикации. Книгу без поля читаем открытой, чтобы уже выпущенные книги, как RepYS, не закрылись. Закрытая книга игрокам не отправляется вовсе: они получают пустую книгу с названием и значком, сервер не считает их прогресс и не принимает их действия и покупки. Операторы (права 2) видят книгу целиком. Импорт FTB пишет `false`, открывает книгу оператор из книги (пакет `PublishPayload`).

Книга одна на сервер: если `book.json` есть в нескольких namespace, берётся первый по алфавиту, об остальных предупреждает `/rysquests validate` (ADR-21). Главы из `chapter_order` идут первыми, остальные после них по id.

`default_theme` пока не применяется: выбор темы один на все моды семьи и хранится в RYSCore (ADR-23).

## Глава: `chapters/<dir>/_chapter.json`

```json
{
  "id": "repys:02_power",
  "title": "chapter.repys.power.title",
  "subtitle": "chapter.repys.power.subtitle",
  "icon": "kubejs:electric_mechanism",
  "epoch": 2,                          // необязательно, для ленты эпох
  "default_view": "map",               // переопределяет книгу
  "groups": [                          // подглавы для рамок на карте
    { "id": "basics", "title": "chapter.repys.power.basics" } ],
  "requires": ["repys:01_create"],     // главы-зависимости (все)
  "hidden": false,
  "section": "story",                  // раздел книги, по умолчанию story
  "off_map": false                     // не на карте: блок «Вне карты», открывается списком
}
```

`off_map` необязательное: глава остаётся в книге и в счёте, но на карте её нет, она в блоке «Вне карты» сайдбара (как «Начало» и «Летопись» RepYS). Автовыбор формы её не считает. Эпохи считаются с 1; `epoch: 0` читается как отсутствие эпохи, так что в книге с эпохами такая глава тоже вне карты (так старые книги RepYS держали вступление и летопись, ADR-51).

Поле `section` заложено для разделов из `09-sections.md`. Сейчас книга показывает только главы с `story`. Глава с другим значением загружается, но в книге не видна.

Прогресс квеста хранит необязательное `times`: сколько раундов повторяемого квеста уже пройдено. Квесты после повторяемого открыты, если он выполнен сейчас или раньше (ADR-46). Старые сохранения читаются как `times: 0`.

Режим `accumulate` у задач на предмет и жидкость устарел: он читается и работает как `observe`, проверка книги предупреждает (ADR-48). Поле главы `requires` проверяется: квест главы не должен зависеть от квеста главы вне цепочки её `requires`; замка на главе нет. Команда награды: необязательный `level` (0–4, по умолчанию 4) для `as_server`; подстановки FTB Quests `{p}`, `{x}`, `{y}`, `{z}`, `{quest}`, `{chapter}`, `{team}`, `{team_id}`, `{long_team_id}`, `{member_count}`, `{online_member_count}`, неизвестные остаются как есть. Задача посещения с `size` [w, h, d] проверяет область блоков от `pos` до `pos + size`, без него `pos` это центр шара с `radius`.

Задача `rysquests:xp`: `levels` или `points`, необязательное `consume` (сдать кнопкой). У задачи на предмет режим `craft` считает скрафченное и выплавленное.

Поле главы `links`: список id квестов других глав, которые показываются и на её карте (ADR-46). Узел-ссылка подписан главой квеста, клик открывает квест в его главе. Ссылка не меняет счёт главы и прогресс.

## Квест: `chapters/<dir>/<quest>.json`

Один файл на квест. Допускается массив квестов в файле `_quests.json` для маленьких книг.

```json
{
  "id": "repys:power/electric_mechanism",
  "chapter": "repys:02_power",
  "group": "basics",
  "title": "quest.repys.power.electric_mechanism.title",
  "subtitle": "quest.repys.power.electric_mechanism.subtitle",
  "text": "quest.repys.power.electric_mechanism.text",
  "icon": "kubejs:electric_mechanism",
  "requires": ["repys:power/wires", "repys:power/dynamo"],
  "requires_mode": "all",              // all | any | {"n": 2}
  "stage_required": null,              // строка стадии или null
  "tasks": [ ... ],
  "rewards": [ ... ],
  "layout": { "pin": false, "x": null, "y": null },
  "milestone": false,                  // веха: крупный узел; старое "size": 2 читается как веха
  "optional": false,
  "hidden": false,                     // не отправлять клиенту, пока зависимости не выполнены
  "repeatable": null,                  // null или {"cooldown_minutes": 60}
  "page": false,                       // true: страница без задач, засчитывается прочтением
  "guide": "repys:create#rotation",    // гайд или его страница, даёт кнопку «Как это работает»
  "tags": ["milestone"],               // milestone: веха в Ленте, key_item: ключевой предмет эпохи
  "draft": false,                      // черновик: игроки его не видят, пока автор не поправит
  "archived": false                    // в архиве: убран из книги без удаления файла
}
```

- `milestone`: веха. Старое `size: 2` читается как веха, при записи пишется `milestone`, а `size` больше не пишется.
- `optional`: необязательный квест не входит в счёт главы, эпохи и книги; его считают отдельно («побочные», `BookCounts`).
- `draft`: черновик. Сервер не отправляет его игрокам и не считает, операторы видят его в редакторе. Так импорт FTB оставляет квест, у которого задачу пришлось заменить галочкой или награду выбросить. Снять флаг должен автор: правка в редакторе.
- `archived`: архив вместо удаления. Игрокам не отправляется, не считается. Квест, который ждёт черновик или квест в архиве, игроки не откроют: проверка книги предупреждает (`requires_draft`, `requires_archived`).
- `layout`: с `pin: true` координаты `x`, `y` ставят квест на ручное место на карте главы (их пишет редактор). Без `pin` координаты только запомнены и карта их не читает: так импорт FTB сохраняет положение квеста из FTB, одна клетка FTB равна 24 единицам, шагу сетки редактора.

Поля `chapter` можно опускать: тогда берётся из папки. `requires` ссылаются только на квесты; зависимость от главы задаётся на главе.

## Гайд: `guides/<id>.json`

Один файл на гайд, тексты в lang. Подробно в `09-sections.md`, раздел «Гайды».

```json
{
  "id": "repys:create",
  "title": "guide.repys.create.title",
  "icon": "create:cogwheel",
  "category": "guide.repys.category.tech",   // необязательно, чип в библиотеке
  "stage": "repys:epoch_3",                  // необязательно, закрыт до стадии
  "stage_title": "guide.repys.stage.epoch_3", // необязательно, название стадии для игрока
  "pages": [
    { "id": "rotation", "title": "guide.repys.create.rotation.title", "text": "guide.repys.create.rotation.text" }
  ]
}
```

## Кастомная вкладка: `sections/<id>.json`

Один файл на вкладку, поле `template`: `matrix`, `cards` или `pages`. Id вкладки это путь файла. Формат шаблонов в `09-sections.md`, примеры в `examples/example_pack`.

## Сделка магазина: `shop/<id>.json`

```json
{
  "id": "repys:iron_bundle",
  "icon": "minecraft:iron_ingot",
  "category": "shop.repys.resources",
  "cost":  [ { "type": "currency", "id": "coin", "amount": 40 } ],
  "gives": [ { "type": "item", "id": "minecraft:iron_ingot", "count": 32 } ],
  "limit": { "per": "player", "count": 3, "reset": "daily" },  // per: player | team; reset: never | daily | weekly
  "stage": "repys:epoch_2",
  "stage_title": "shop.repys.epoch_2",
  "quest": "repys:power/wires",                                 // закрыта до выполнения квеста командой
  "lock_text": "shop.repys.wait_wires"                          // необязательно, своя строка закрытой карточки (с 0.2.7)
}
```

Предмет в `gives` может нести компоненты, как предмет награды (с 0.2.6). Игрок получает его как есть:

```json
{
  "id": "repys:long_rockets",
  "cost":  [ { "type": "currency", "id": "coin", "amount": 2 } ],
  "gives": [ { "type": "item", "id": "minecraft:firework_rocket", "count": 16,
               "components": { "minecraft:fireworks": { "flight_duration": 3 } } } ],
  "limit": { "per": "team", "count": 1 }
}
```

- `components` разрешены только в `gives` и только у предмета. В `cost` и у валюты они ошибка проверки книги (`offer_cost_components`, `offer_currency_components`), такая сделка не попадает в книгу: платить можно только простым предметом.
- Место в инвентаре считается по стекам того же предмета с теми же компонентами: ракета с долгим полётом не ложится на обычные ракеты.
- Поиск сделок, печатающих деньги (`ShopCycles`), считает предмет с компонентами отдельным товаром: продать его магазину нельзя.
- Компонент мода, которого нет в игре, не читается: сделка с ним выпадает из книги с ошибкой разбора файла.

Лимит `{ "per": "team", "count": 1 }` (по умолчанию `reset: never`) это покупка один раз на команду. Карточка пишет «1 раз на команду», после покупки «куплено командой» и «в команде» вместо кнопки. Использованный лимит команды не теряется при переходах (с 0.2.6):
- ушедший из команды и каждый участник распущенной команды уносят с собой то, что команда уже купила: купить это ещё раз в одиночку нельзя;
- вступивший добавляет команде то, что купил сам, сверх уже учтённого: «вышел, купил, вернулся» не даёт второй копии, повторное вступление ничего не удваивает;
- при слиянии команд использованное обеими складывается, отмена слияния возвращает обе стороны как были;
- то же для команд собственных команд мода (`/rysquests team`).

Трофей босса (с 0.2.7) это сделка, у которой `quest` указывает на уровень достижения-убийства. Уровень достижения это скрытый квест `<ns>:_achievements/<id достижения>/<tier>`, его прогресс общий для команды, как у любого квеста, поэтому первое убийство босса кем-то из команды открывает сделку всем её участникам навсегда:

```json
{
  "id": "repys:trophy_ignitium",
  "category": "shop.repys.trophies",
  "cost":  [ { "type": "currency", "id": "coin", "amount": 500 } ],
  "gives": [ { "type": "item", "id": "cataclysm:ignitium_ingot", "count": 1 } ],
  "quest": "repys:_achievements/slayer_ignis/gold"   // achievements/slayer_ignis.json: task rysquests:kill, entity cataclysm:ignis
}
```

- Убийство засчитывается, если последний удар нанёс настоящий игрок: дробилки и раздатчики (`FakePlayer`) не считаются. Достижение должно иметь задачу `rysquests:kill` с одной сущностью.
- Закрытая карточка сама пишет «победи: <имя сущности>», деталь объясняет, что сделка откроется всей команде. Своя строка задаётся `lock_text` (ключ перевода или текст), она важнее `stage_title` и строки квеста.
- Переходы между командами идут по правилам прогресса квестов: вступивший с переносом прогресса приносит свои победы команде, без переноса его победы остаются в его личной записи; ушедший с копией прогресса уносит победы команды, без копии начинает без них, а у команды победа остаётся; при слиянии победы обеих команд складываются.
- В книге с `progress_mode: solo` победа у каждого своя, с `server` общая на сервер.

Накопительная сделка (с 0.2.7) это сделка с `delivery: true`. Предметы из `cost` сдаются частями, валюта из `cost` списывается только при выдаче товара:

```json
{
  "id": "repys:trophy_ignitium",
  "category": "shop.repys.trophies",
  "delivery": true,
  "cost": [
    { "type": "item", "id": "repys:reinforced_alloy", "count": 4096 },
    { "type": "item", "id": "repys:plasma_cell", "count": 512 },
    { "type": "currency", "id": "coin", "amount": 500 }
  ],
  "gives": [ { "type": "item", "id": "cataclysm:ignitium_ingot", "count": 1 } ],
  "quest": "repys:_achievements/slayer_ignis/gold"
}
```

- Кнопка «Сдать из инвентаря» берёт из основного инвентаря простые стаки (без компонентов), по каждой строке не больше, чем ей не хватает. Строки с одним предметом складываются.
- Счёт общий для команды (`teamOf` в режиме команды, как лимит на команду), одиночка копит на себя. Карточка показывает среднее по строкам: полная строка из трёх это треть.
- Когда все строки собраны, «Забрать» платит монеты (свои или из казны по праву `spend_treasury`), выдаёт `gives` и снимает со счёта одну норму. Сданное сверх нормы (оно бывает только после слияния или вступления) остаётся на следующий круг. Лимит сделки, если задан, считает выдачи.
- Без предмета в `cost` или с одной валютой в `gives` это ошибка проверки книги (`offer_delivery_items`, `offer_delivery_sale`), сделка не попадает в книгу.
- Переходы между командами (ADR-54): вступивший приносит команде свой личный счёт целиком, его счёт обнуляется; ушедший ничего не уносит при любом правиле команды о прогрессе, у команды остаётся всё; при роспуске счёт остаётся на записи команды и возвращается вместе с ней из архива; при слиянии счёт складывается, отмена слияния возвращает слитой команде не больше, чем у объединённой ещё осталось. Предметы между счетами только перемещаются и никогда не копируются.
- Оператор обнуляет счёт командой `/rysquests shop delivery reset <игроки> [сделка]`: счёт команды каждого игрока и его личный.

Редактор книги (вкладка «Магазин», с 0.2.7, ADR-58) пишет те же поля и не теряет те, которых не показывает (`icon`, `stage`, `stage_title`, вторую валюту):
- переключатель «Поставка» ставит `delivery: true`; строки «Сдать поставкой» это предметы `cost` с числом до 2 147 483 647, валюта `cost` остаётся ценой. Без предмета поставка не включается (берётся предмет из руки, простой), последнюю строку убрать нельзя, продажей поставка не становится. Выключенная поставка оставляет предметы в `cost`: они платятся сразу вместе с монетами;
- «Открывается: Сразу | После квеста | После победы» пишет `quest`: веху книги или первый уровень достижения-убийства (`<ns>:_achievements/<id>/<первый tier>`);
- «Строка закрытой карточки» пишет `lock_text` ключом `shop.<ns>.<путь сделки>.lock` (или своим ключом сделки, если он уже есть), текст уходит в lang-файл папки редактора; пустое поле убирает `lock_text`;
- цена меняет первую валюту стороны цены и сохраняет её название (жетон остаётся жетоном);
- при сохранении в lang-файл принимаются строки ключей `title`, `category`, `lock_text`, `stage_title` сделки.

Продажа это сделка, которая даёт только валюту. Название валюты берётся из ключа `rysquests.currency.<id>`. Награда квеста: `{ "type": "rysquests:currency", "id": "coin", "amount": 50 }`, с `team_mode: once` идёт в казну команды. Раздел включается строкой `shop` в `sections` файла `book.json`.

## Блок «Приёмщик»: `rysquests:shop_receiver`

С 0.2.7. Блок с сущностью блока, без слотов и без тика. Рецепта в моде нет: его даёт сборка; без рецепта блок берут в творческом режиме (вкладка «Функциональные блоки») или командой `/give @s rysquests:shop_receiver`. Состояние блока `lamp`: `off`, `green`, `yellow`, `red`.

Сущность блока хранит под ключом `receiver`:

```
receiver {
  owner: uuid, owner_name: string,      // кто поставил; нет у блока, поставленного командой, пока его не откроют
  program: string,                      // режим: "rysquests:sell" или "rysquests:delivery"; "rysquests:trial" занят под «Испытания»
  offer: string,                        // id выбранной сделки, необязательно
  treasury: bool,                       // монеты продажи идут в казну команды владельца
  buffer: { <item id>: long },          // принятое продажей и ещё не сложившееся в целый лот
  accepted: long, lots: long, earned: long,  // счётчики окна с момента установки или сброса
  status: string,                       // последнее состояние: WORKING, WAITING, FULL, NO_TEAM, CLOSED, LIMIT, NO_OFFER, NO_OWNER
  pending: bool,                        // принятое ждёт расчёта
  comparator: string,                   // с 0.2.7 (М7): что читает компаратор, "state" или "fill"; нет ключа: "state"
  notify: bool                          // с 0.2.7 (М7): сообщать владельцу, когда блок встал; нет ключа: да
}
```

Компаратор у «Приёмщика»: по состоянию 15 (работает), 10 (ждёт), 5 (стоит), 0 (выключен); по заполненности как у сундука, от того, сколько лежит в буфере продажи из 256 лотов каждого предмета (у поставки буфера нет, там 0).

- Режим это id программы. Новый режим добавляется новой программой, формат блока не меняется; блок с незнакомым режимом ничего не берёт.
- Продажа берёт только предметы из `cost` выбранной продажи и только простые стаки, не больше 256 лотов каждого предмета в буфере. Раз в секунду после поступления продаются все целые лоты одной сделкой, остаток ждёт в буфере. При поломке блока и при смене сделки целые лоты продаются, остаток выпадает предметами.
- Поставка сдаёт поступившее сразу в счёт команды владельца (`deliveries`), по каждой строке не больше недостающего.
- Предмет из буфера, мода которого больше нет, при загрузке отбрасывается.

## Блок «Выдача»: `rysquests:shop_dispenser`

С 0.2.7. Блок с сущностью блока и своим слотом на 9 ячеек, покупает раз в секунду. Рецепта в моде нет, как и у «Приёмщика». Состояние блока `lamp`: `off`, `green`, `yellow`, `red`.

Сущность блока хранит под ключом `dispenser`:

```
dispenser {
  owner: uuid, owner_name: string,      // кто поставил; нет у блока, поставленного командой, пока его не откроют
  offer: string,                        // id выбранной сделки покупки, необязательно
  treasury: bool,                       // платить из казны команды владельца
  output: string,                       // куда класть товар: "down", "up", "north", "south", "west", "east" или "self" (свой слот)
  budget_on: bool, budget: long,        // «Потратить не больше»: монет с последнего сброса счётчика
  reserve_on: bool, reserve: long,      // «Оставить на счету не меньше»
  stock_on: bool, stock: long,          // «Держать в инвентаре не больше»: штук товара там, куда блок кладёт
  redstone: bool,                       // работать только при сигнале редстоуна
  comparator: string,                   // "state" или "fill"
  notify: bool,                         // сообщать владельцу, когда блок встал; нет ключа: да
  slot: { Items: [...], Size: 9 },      // свой слот, формат ItemStackHandler NeoForge
  lots: long, spent: long,              // счётчики с последнего сброса или смены сделки; spent считает и «Потратить не больше»
  status: string                        // последнее состояние: WORKING, WAITING, RESERVE, BUDGET, STOCKED, NO_SPACE, NO_TEAM, NO_RIGHT, CLOSED, LIMIT, REDSTONE, NO_OFFER, NO_OWNER
}
```

- Подходят сделки, где цена только монеты, а выдаются предметы. Ограничения считают первую валюту цены; «Держать не больше» считает первый предмет выдачи, тот же предмет с теми же компонентами.
- Порядок одной покупки: сделка открыта команде владельца и лимит не исчерпан, право на казну, три ограничения, симуляция вставки всего лота, списание монет, настоящая вставка. Не больше 64 лотов за раз.
- Числа ограничений от 0 до 10^12. Смена сделки обнуляет счётчики.
- Трубы забирают из своего слота с любой стороны, класть в блок ничего нельзя. Пока в своём слоте остаток (товар не поместился в инвентарь сбоку), блок сначала отдаёт его и ничего не покупает. При поломке блока содержимое слота выпадает.
- Компаратор: по состоянию 15, 10, 5, 0, как у «Приёмщика»; по заполненности своего слота, как у сундука.

## Достижение: `achievements/<id>.json`

```json
{
  "id": "repys:factory_worker",
  "category": "achievement.repys.tech",
  "icon": "minecraft:crafter",
  "hidden": false,
  "task": { "type": "rysquests:stat", "stat": "minecraft:custom", "target": "minecraft:jump" },
  "tiers": [
    { "tier": "bronze", "amount": 10,   "rewards": [ { "type": "rysquests:currency", "id": "coin", "amount": 10 } ] },
    { "tier": "silver", "amount": 100,  "rewards": [ { "type": "rysquests:title", "id": "title.repys.worker" } ] },
    { "tier": "gold",   "amount": 1000 }
  ]
}
```

Необязательное `archived: true` убирает достижение в архив: игрокам оно не отправляется, его уровни не считаются. Цвет уровня задаёт место, а не имя: последний уровень золотой, перед ним серебряный, все более ранние бронзовые (`Achievement.medal`); `tier` теперь только id уровня.

Количество в `task` задавать не нужно: его подставляет `amount` уровня. Подходят `kill`, `stat`, `item` (без `mode` это `observe`) и `advancement` (у неё один уровень с `amount: 1`); задача со сдачей или галочкой не считается сама, валидатор предупредит. Тексты: ключи `achievement.<ns>.<id>.name`, `.text`, `.hint` (подсказка скрытого), либо поля `title`, `text`, `hint`. Раздел включается строкой `achievements` в `sections`.

## Структура: `structures/<id>.json`

Поля `mapping` и `pattern` как у мультиблока Patchouli, необязательное `title`. Id это путь файла. Слои сверху вниз, пробел воздух, `_` что угодно, `0` опорный блок. Вставка на страницу: `[[structure:repys:assembly_hall|подпись]]`. Примеры и подробности в `GUIDE.md`, раздел 10.

## Задачи

Все задачи имеют `type`, `count` (по умолчанию 1), `mode` где применимо (`consume` | `observe` | `accumulate`), необязательный `title`.

```json
{ "type": "rysquests:item", "item": "#c:plates/copper", "count": 16, "mode": "consume" }
{ "type": "rysquests:item", "item": "kubejs:electric_mechanism", "count": 3, "mode": "observe",
  "nbt": { "strict": false, "components": { ... } } }
{ "type": "rysquests:item", "any_of": ["minecraft:oak_log", "minecraft:birch_log"], "count": 8 }
{ "type": "rysquests:checkbox", "title": "task.read_and_confirm" }
{ "type": "rysquests:advancement", "advancement": "repys:electrician" }
{ "type": "rysquests:stat", "stat": "minecraft:mined", "target": "minecraft:iron_ore", "count": 12, "mode": "accumulate" }
{ "type": "rysquests:visit", "dimension": "minecraft:the_nether" }
{ "type": "rysquests:visit", "biome": "#minecraft:is_desert" }
{ "type": "rysquests:visit", "structure": "minecraft:desert_pyramid" }
{ "type": "rysquests:visit", "pos": [100, 64, -200], "radius": 16, "dimension": "minecraft:overworld" }
{ "type": "rysquests:kill", "entity": "minecraft:skeleton", "count": 10 }
{ "type": "rysquests:fluid", "fluid": "minecraft:lava", "amount": 4000, "mode": "consume" }
```

`item.item` принимает id предмета, тег `#…`, или массив через `any_of`. `mode` для `item`: `consume` изымает при сдаче (по умолчанию), `observe` засчитывает наличие, `accumulate` считает всё, что когда-либо прошло через инвентарь (по событиям подбора/крафта). Для `stat` только `accumulate`. При общем прогрессе (`team`, `server`) значение `stat` это сумма статистик всех, кто делит прогресс, а для серий `time_since_death` и `time_since_rest` самая длинная текущая серия, которая после смерти начинается заново (с 0.2.8, ADR-61).

Расширение типов: `type` диспетчеризуется через реестр `TaskType` (Codec dispatch по `type`). Моды и KubeJS регистрируют свои.

## Награды

```json
{ "type": "rysquests:item", "item": "minecraft:gold_ingot", "count": 8 }
{ "type": "rysquests:item", "item": "minecraft:diamond_sword", "components": { "minecraft:enchantments": { ... } } }
{ "type": "rysquests:choice", "of": [ {...item...}, {...item...} ] }
{ "type": "rysquests:random", "of": [ {...item...}, {...item...} ], "weights": [3, 1] }   // weights необязательны
{ "type": "rysquests:xp", "levels": 2 }           // или "points": 100
{ "type": "rysquests:command", "command": "give @s minecraft:emerald 1", "as_server": true }
{ "type": "rysquests:loot_table", "table": "repys:quests/power_tier", "rolls": 1, "show_chances": true }
{ "type": "rysquests:stage", "stage": "2" }
```

Правила выдачи: награды выдаются по действию «Забрать» (не автоматически), в инвентарь; если места нет, остаются «к получению». `choice` требует выбора клиентом: «Забрать всё» выдаёт остальные награды, а квест с выбором ждёт, пока игрок откроет его и выберет. Для `team` режима на награде есть `team_mode`: `each` (каждому игроку) | `once` (один раз на команду, забирает первый).

Награда `command` выполняется от игрока, который её забирает, в его позиции: `@s` и `@p` указывают на него. `as_server: true` повышает только права команды, источник остаётся тем же. Пример стадии RYScope: `ryscope stage grant @s config:iron_age`.

## Миграции: `migrations.json`

```json
{
  "migrations": [
    { "id": "2026-11-01-rename-el-mech", "op": "rename",
      "from": "repys:power/el_mech", "to": "repys:power/electric_mechanism" },
    { "id": "2026-11-02-merge-wires", "op": "merge",
      "from": ["repys:power/wires_a", "repys:power/wires_b"], "to": "repys:power/wires",
      "strategy": "max" },
    { "id": "2026-11-03-remove-old-test", "op": "remove", "from": "repys:power/old_test" },
    { "id": "2026-11-05-ftbq-import", "op": "map",
      "from_ftbq": { "1A2B3C4D": "repys:power/electric_mechanism", "...": "..." } }
  ]
}
```

Миграции применяются по порядку, каждая один раз (`id` запоминается в прогрессе). `remove` переносит в архив, не удаляет. `map` используется импортёром FTB Quests и переносит прогресс по числовым id FTB.

`last_chapter` хранит главу квеста, который игрок выполнил последним своим действием (сдача, отметка, проверка его инвентаря, крафт, убийство). Выполнение командой оператора её не меняет. Сервер шлёт её только этому игроку в `ProgressPayload`; товарищи по команде получают свою. Нет записи: клиент берёт первую незавершённую главу. Строки истории магазина без `treasury` считаются личным кошельком.

## Черновик редактора

Несохранённая работа редактора квестов живёт на диске клиента между сеансами: `rysquests/drafts/<сервер или мир>/<namespace>~<путь главы>.json` в папке игры, файл на главу (`EditorDrafts`, `ClientDrafts`). В файле глава, все её квесты, набранные тексты, язык, версия главы, с которой начата правка, признак новой главы и время записи. После сохранения в книгу или отказа от правок черновик удаляется.

Редактор книги (шаг 10) держит один черновик на всю книгу: `rysquests/drafts/<сервер или мир>/book_draft.json` (`BookDraft`, `EditorDrafts.saveBook`). В нём главы целиком с версией, с которой начата правка, настройки книги, товары и убранные товары, достижения с их задачей, гайды, вкладки автора, набранные тексты и по строке словами на каждую правку: их число это N в «Сохранить · N», они же список вопроса «Сохранить N правок?». Файл пишется после каждой правки. После сохранения или «Не сохранять» он переименовывается в `book_draft.json.old`, а не удаляется.

Сохранение идёт частями по одной: сначала настройки книги, товары и достижения (`BookEditsSavePayload`; книга, у которой ещё нет глав, пишется закрытой для игроков), потом главы (`QuestEditorSavePayload` с версией главы), гайды и вкладки (`EditorSavePayload`). Убранный товар уходит из папки редактора в `_removed/` той же папки; товар из другого датапака отсюда не убрать (`rysquests.editor.error.offer_elsewhere`). Достижение пишется файлом `achievements/<id>.json` вместе с `task`.

## Импорт FTB Quests

Импорт пишет книгу закрытой (`published: false`), группы глав FTB как эпохи с `imported: true`, положение квеста из FTB в `layout.x/y` без `pin`, `size` FTB 2 и больше как `milestone`. Задача, которой в книге нет, становится галочкой с заголовком `rysquests.import.unconverted_task`, а квест черновиком; квест, у которого выброшена награда, тоже черновик. Файл, который не прочитался, останавливает импорт до записи: отчёт называет файл и строку, импорт можно повторить без этого файла (пакеты `FtbqImport*Payload`, класс `FtbqImportService`). Отчёт по видам: перенесено, куда попало, нужна ручная правка (`ImportReport`), полный список в `config/rysquests/import/import-report.md`.

## Папка редактора

Редактор квестов пишет файлы квестов и глав сюда же, в тот же относительный путь, где квест лежит в книге, и файлы по формату этого документа (ADR-39). Настройка `editorFolder` (общий конфиг), по умолчанию `config/rysquests/pack`. Внутри раскладка пака. Переводы и картинки из неё, на которые ссылается книга, идут клиентам вместе с книгой и важнее клиентских ресурсов (ADR-35).

## Lang

`assets/<ns>/lang/ru_ru.json`, `en_us.json`. Ключи по шаблону `quest.<ns>.<chapter>.<quest>.title|subtitle|text`, `chapter.<ns>.<chapter>.title`, `task.<…>`. Валидатор сообщает о ключах без перевода в активном языке.

## Разметка текста

Используется в `text`, `subtitle`, страницах:

- `[[item:minecraft:redstone]]` иконка + имя, клик → рецепты во вьюере; `[[item:...|подпись]]`.
- `[[quest:repys:power/wires]]` ссылка на квест.
- `[[recipe:kubejs:electric_mechanism]]` одна в строке страницы гайда: рецепт как его рисует JEI, после `#` можно указать категорию (`[[recipe:create:brass_ingot#create:mixing]]`); в тексте: как `item`.
- `[[guide:repys:create#rotation]]` ссылка на гайд или его страницу.
- `[[image:repys:textures/guides/wheel.png|подпись]]` картинка, одна в строке.
- `[[ponder:create:mechanical_crafter]]` открывает размышление Ponder, без него ссылка становится текстом.
- `[[url:https://…|подпись]]`, `[подпись](https://…)` или голый адрес `https://…`: ссылка на сайт (с 0.2.8, ADR-61). Открываются только http и https; по клику игра спрашивает, открыть ли, как в чате. Без подписи показывается адрес без `https://`.
- `**жирный**`, `__курсив__`, `!!предупреждение!!` (янтарный блок), `>>спойлер<<`.
- Переносы строк `\n`, абзац пустой строкой.

Парсер в `rysquests.client.markup`, синтаксис как в RYScope; кандидат на перенос в RYSCore.

## Канонический порядок полей

При записи (редактор, импортёр) поля идут в порядке, в котором перечислены в этом документе. Это делает диффы в git читаемыми. Загрузчик порядок не требует.

## Раскладка карты: `layout.json`

Готовая раскладка лежит рядом с `book.json`: `data/<namespace>/rysquests/layout.json`. Сервер читает её вместе с книгой (из того же namespace, что `book.json`) и отправляет игрокам внутри книги, так что игрок карту не считает.

```json
{
  "form": "serpentine",                // форма, в которой разложено, не auto
  "hash": "9f2c…",                     // layoutHash книги, для которой разложено
  "nodes": {                           // центр узла квеста на полотне, [x, y]
    "repys:b00_e1_andesite/andesite_alloy": [120, 48]
  },
  "areas": {                           // прямоугольники [x, y, w, h]: главы по id, эпохи как epoch:<номер>
    "repys:b00_e1_andesite": [0, 0, 960, 540],
    "epoch:1": [-40, -40, 2400, 620]
  },
  "decor": {                           // всё, что полотно рисует кроме узлов; числа с точностью до десятой
    "regions": {                       // форма главы: [0, x, y, w, h] прямоугольник, [1, ширина, x0, y0, x1, y1, …] полоса вдоль линии, [2, cx, cy, r] круг
      "repys:b00_e1_andesite": [0, -5, 0, 412.5, 230]
    },
    "labels": {                        // где стоит номер главы и насколько широкой может быть её подпись: [x, y, ширина]
      "repys:b00_e1_andesite": [201.3, 0, 404.5]
    },
    "wheels": [[60, 115, 0, 16, 28]],  // орбиты колеса: [cx, cy, индекс главы, r1, r2, …]
    "marks": [[1, -15, -2, -15, 232, 1, 1]],  // границы эпох: [эпоха, x1, y1, x2, y2, словами 1/0, сторона подписи 1 вправо, -1 влево, 2 вниз, -2 вверх]
    "arms": [],                        // подписи разделов галактики: [эпоха, x, y, наружу x, наружу y]
    "turns": [[1300, 115, 1330, 115, 1330, 375, 1300, 375]]  // поворот ствола между рядами серпантина: ломаная
  }
}
```

Поле `decor` необязательное: раскладка без него (старый файл) считается неполной, и клиент раскладывает карту сам. Какие квесты стоят в центре колёс, в файле не пишется: клиент выводит это из книги тем же правилом, что раскладка.

Раскладку считает только клиент. Файл пишет сервер по пакету `LayoutSavePayload` от клиента оператора: его шлют «Сохранить» в редакторе, «Сохранить раскладку» в «Проверке» и ответ на команду `/rysquests layout bake` (сервер просит клиент оператора пакетом `LayoutBakeRequestPayload`). Сервер принимает раскладку только для книги, какая она сейчас (хеш совпал), и пишет её через папку редактора. Файл пишется построчно: узел или область на строку, по алфавиту, чтобы большая книга читалась в диффе. Раскладка с чужим хешем всё равно уходит игрокам, но клиент считает карту сам, а проверка книги пишет замечание `layout_stale`.

## Хэш книги

- `hash`: SHA-256 от канонического JSON всех квестов, глав, гайдов, вкладок, сделок, достижений и структур после линковки. Версия книги целиком, для проверки совпадения клиент/сервер.
- `layoutHash` (`BookHash.layout`): версия того, от чего зависит карта: форма, эпохи (только признак импорта), главы раздела `story` по порядку книги с эпохой, `off_map`, `hidden`, подглавами и ссылками, и живые квесты этих глав (не черновики, не архив и не награды эпох, 0.2.7) с главой, подглавой, зависимостями, режимом зависимостей, вехой, `optional`, `hidden` и ручным местом. Тексты, задачи и награды не входят: исправленная опечатка не делает раскладку устаревшей. Игрок получает книгу без черновиков и приходит к тому же хешу.
- `chapterVersion` (`BookHash.chapterVersion`): версия одной главы для редактора, канонический JSON главы и всех её квестов. Редактор отправляет в `QuestEditorSavePayload` версию, с которой начата правка; если глава с тех пор изменилась, сервер отклоняет сохранение причиной `rysquests.editor.error.conflict` (с именем оператора, который сохранил главу последним) или `…conflict_files`, если её изменили файлами. Повторное сохранение с `force` пишет поверх. Глава, которой ещё нет, имеет версию `""`.

## Прогресс (внутренний формат, NBT через Codec)

```
ProgressStore {
  version: int,
  applied_migrations: [string],
  guide_pages: { <uuid игрока>: ["<guide id>#<page id>"] },
  pinned_ways: { <uuid игрока>: ["<вкладка>#<строка>#<столбец>#<способ>"] },
  wallets: { <uuid игрока или команды>: { <валюта>: long } },
  shop_usage: { <uuid игрока или команды>: { <сделка>: { period: long, count: int } } },
  counted_usage: { <uuid игрока>: { <сделка>: { period: long, count: int } } },  // с 0.2.6: сколько своих покупок игрока по лимитам на команду команда уже учла
  shop_history: { <uuid игрока>: [ { time, delta, currency, ref, times, treasury } ] },  // treasury: из казны команды; с 0.2.7 сделки блоков владельца копятся в одной строке (delta и times складываются), формат тот же
  last_chapter: { <uuid игрока>: <chapter id> },   // глава последнего выполнения, личная
  titles: { <uuid игрока>: [<ключ титула>] },
  active_title: { <uuid игрока>: <ключ титула> },
  owed_rounds: { <uuid игрока>: { <quest id>: { tasks, completed, claimed, times } } },  // незабранный круг повторяемого квеста, личный
  deliveries: { <uuid команды или игрока>: { <цель>: { <item id>: long } } },  // с 0.2.7: сданное в накопительную сделку; цель это id сделки, может быть и не сделкой
  teams: { <uuid>: {
    quests: { <quest id>: { tasks: [int], completed: long, claimed: [int] } },   // состояние вычисляется из них
    pinned: [<quest id>],
    archive: { <old id>: {...} }
  } }
}
```

Формат может меняться между версиями мода с собственной миграцией (`version`).

`owed_rounds` (0.2.5): повторяемый квест в команде начинает новый круг, когда один участник забрал все свои награды. Что остальные не успели забрать, остаётся у каждого в `owed_rounds`: снимок круга (`tasks`, `completed`) и забранные награды этого круга (`claimed`, вместе с наградами «одному на команду», которые уже взял кто-то другой). `times` здесь значит число следующих завершённых кругов, из которых игрок ещё ничего не брал: книга показывает ему сначала самый старый круг. Пока запись есть, игрок видит квест выполненным и забирает награды этого круга; новый круг команды идёт дальше, задачи сдаёт и он. Когда забрано всё, запись убирается (или переходит к следующему кругу). Старые сохранения без поля читаются как раньше.
