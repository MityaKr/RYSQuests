# 07 · Решения (ADR)

Формат: номер, решение, почему, что отвергнуто. Новые решения добавлять снизу, старые не переписывать (помечать «отменено ADR-N»).

## ADR-1 · Один Gradle-проект, два пакета (отменено ADR-23)
RYScore живёт пакетом `works.repka.ryscore` внутри jar RYSQuests, с запретом зависимостей от `rysquests`. Выделение в отдельный мод, когда появится второй потребитель. Отвергнуто: мультимодульный проект сразу (лишняя сложность сборки без второго потребителя).

## ADR-2 · ModDevGradle
Сборка через ModDevGradle. Отвергнуто: NeoGradle (тяжелее), Architectury (не нужен без Fabric в MVP).

## ADR-3 · Строковые id и один файл на квест
`ResourceLocation` для всех сущностей; один JSON на квест; порядок полей стабилен. Причина: git, генераторы, миграции. Отвергнуто: числовые id (FTB Quests), один файл на главу как основной формат (допускается как альтернатива).

## ADR-4 · Сервер авторитетен, прогресс в SavedData
Прогресс хранится в одном `SavedData` на сервер, ключ команда (UUID). Клиент получает снимок при входе и диффы. Отвергнуто: data attachments на игроке (неудобно для командного режима), хранение на клиенте.

## ADR-5 · Проверка задач по событиям, редкий тик с разносом
Где есть событие, используется событие; `observe`/`stat`/`visit` раз в 20 тиков с разносом по игрокам и кэшем хэша инвентаря. Отвергнуто: проверка каждый тик.

## ADR-6 · Миграции через `migrations.json`, применяются один раз, с архивом
Удаление никогда не теряет данные: записи уходят в архив. Отвергнуто: автоматическое угадывание переименований по похожести названий.

## ADR-7 · Автораскладка на клиенте с кэшем на диске
Слоёный алгоритм считается на клиенте в фоне, кэш по хэшу книги. Отвергнуто: раскладка на сервере (разные размеры экранов и свёртки у игроков), хранение координат в датапаке как обязательное.

## ADR-8 · Книга отправляется целиком и сжато один раз
При входе и `/reload`. Отвергнуто: ленивая подгрузка глав (сложнее, выигрыш мал при сжатии).

## ADR-9 · Награды выдаются по действию «Забрать»
Не автоматически, кроме режима, который автор включит позже. Причина: инвентарь полон, выбор `choice`, командные правила. Отвергнуто: авто-выдача по умолчанию.

## ADR-10 · Редактор в игре не в MVP
Авторский процесс это генератор; редактор после MVP. Файловый формат проектируется так, чтобы редактор мог его писать без потери порядка полей.

## ADR-11 · Концепт «Компаньон» не учитывается
Решение автора. Не проектировать под него специально; не блокировать (события и API позволяют добавить панель позже).

## ADR-12 · Темы через JSON в ресурспаке, nine-slice текстуры (отменено ADR-14)
Скругления и тени рисуются спрайтами, токены цветов тонируют. Отвергнуто: шейдеры для blur в MVP.

## ADR-13 · Мост к вьюеру рецептов как интерфейс, JEI первой реализацией (дополнено ADR-20)
Отвергнуто: жёсткая зависимость от JEI.

## ADR-14 · Интерфейс рисуется процедурно, тема состоит только из токенов
Отменяет ADR-12. Скругления, рамки, тени и бевели рисует `Draw` в пикселях устройства. `Theme` даёт примитивы `panel`, `card`, `plate`, `slot`, `hover`, `button`, `input`, `tab`, `chip`, `tooltipBox` и признак `beveled()` для Vanilla. Тема это JSON с полями `id`, `name`, `font`, `colors`, `metrics`, `effects`; раздела `textures` нет. Причина: формат уже работает в RYScope, углы гладкие на любом GUI Scale, для новой темы достаточно одного JSON. Отвергнуто: nine-slice через `blitSprite` (текстуры на каждую тему), свой формат темы.

## ADR-15 · RYScore повторяет контракты RYScope (отменено ADR-23)
Классы `works.repka.ryscore.ui.Draw`, `ryscore.ui.Loading`, `ryscore.ui.theme.Theme`, `ryscore.ui.theme.ThemeManager` с теми же именами классов и методов. Имена и значения токенов, а также цепочка запасных токенов берутся из RYScope, своих токенов не вводим. Внутри `ryscore` только классы Minecraft, без API NeoForge, иначе код не перенести в `common` RYScope. Дополняет ADR-1. Причина: библиотеку потом сливают простым переносом. Отвергнуто: свои имена и своя иерархия пакетов.

## ADR-16 · Исключение из правила Codec для тем (отменено ADR-23)
`Theme` читает JSON через Gson, как в RYScope. Тема это открытые словари токенов с запасными значениями, и кодек сломал бы слияние простым переносом. Исключение только для тем; данные квестов и сеть остаются на `Codec` и `StreamCodec`.

## ADR-17 · Одна выбранная тема на оба мода (отменено ADR-23)
Наши копии тем лежат в `assets/ryscore/ryscore_themes/`. Папка отдельная, потому что `ThemeManager` RYScope ищет `ryscope_themes` во всех namespace, и наши файлы там стали бы дублями в его списке. Если RYScope установлен, через отражение читается только `ThemeManager.get().id`, и по этому id тем же парсером читается файл `assets/<ns>/ryscope_themes/<имя>.json`, поэтому работают и темы из ресурспаков. Настройка темы в книге при этом скрыта. В состав входят Slate, Vanilla и Glass, потому что игрок RYScope может быть на любой из них. Отвергнуто: жёсткая зависимость; чтение токенов из объекта темы RYScope отражением на каждый вызов; сопоставление только встроенных тем.

## ADR-18 · Единицы интерфейса это пиксели GUI
Числа в макетах делятся на 2,2 (константа `DESIGN_SCALE` в `Theme`): слот 40 в макете это 18 GUI. Окно книги 1200×728 это 545×331 GUI, колонки 232 и 392 это 105 и 178. Три колонки помещаются на GUI Scale 2 и 3 при 1920×1080; на Scale 4 (480×270) работает компактный режим. Отвергнуто: считать пиксели макета пикселями GUI.

## ADR-19 · Поведение окон общее с RYScope
Окно открывается сразу, тяжёлый расчёт идёт вне кадра или порциями, внутри окна индикатор `Loading`. Окна не прыгают: верхний край закреплён, рост только вниз. Длинных подсказок в строке внизу нет, вместо них значок «i» и подсказка при наведении. Шапка не дублирует то, что уже видно. Вкладки вместо стрелок «1/7». Панели обходят чужие области экрана. Причина: решения приняты в RYScope после жалоб игроков, и игрок не должен видеть шов между модами.

## ADR-20 · Отдельного моста к RYScope нет
Дополняет ADR-13. С RYScope в игре всегда есть JEI, а его `IRecipesGui.show` открывает окно RYScope, поэтому достаточно `JeiBridge`. Компиляция против минимальной версии JEI 19.42.0.379. С RYScope JEI стартует в фоновом потоке `RYScope-JEI`: `onRuntimeAvailable` и регистрация только сохраняют ссылки, без GL, мира и экранов. Отвергнуто: `RyscopeBridge` с жёсткой зависимостью.

## ADR-21 · Один `book.json` на книгу
Книга одна на сервер. Если `book.json` есть в нескольких namespace, берётся первый по алфавиту, об остальных предупреждает валидатор. Главы из `chapter_order` идут первыми, остальные по id. Причина: правило детерминировано и видно в отчёте, а настройки книги не имеют смысла складывать. Отвергнуто: слияние полей из нескольких файлов; выбор по приоритету датапаков (порядок между namespace не определён в `listResources`).

## ADR-22 · Большую книгу режет транспорт NeoForge
`BookSyncPayload` отправляется одним пакетом, `GenericPacketSplitter` сам делит его на части. Причина: штатный механизм с пределом 128 МБ, сжатая книга на порядки меньше. Отвергнуто: свой протокол частей из первого варианта плана.

## ADR-23 · RYSCore это отдельный мод
Отменяет ADR-1, ADR-15, ADR-16 и ADR-17. Общая основа семьи вынесена в мод `ryscore` (`C:\Projects\RepYS\RYSCore`), мы вкладываем его через jarJar с диапазоном `[1.0.0,2.0.0)` и объявляем обязательной зависимостью. Пакет `works.repka.ryscore` у нас не создаётся и классы кора не копируются: два мода с одним Java-пакетом не запускаются вместе (`ResolutionException`). Используем готовое: `theme.Theme`, `theme.ThemeManager`, `ui.Draw`, `ui.Loading`. Темы лежат в `assets/<ns>/ryscore_themes`, встроенные `ryscore:slate`, `ryscore:vanilla`, `ryscore:glass`; выбор темы общий и хранится в ядре, отражение за RYScope не нужно. Моды семьи общаются только через интерфейсы кора. Виджеты, доска поверх мира и разметка, которых в коре ещё нет, живут в `works.repka.rysquests`, а когда понадобятся второму моду, переносятся в кор. Папка кора только для чтения, правки идут через блок «Запрос к RYSCore». Отвергнуто: держать `ryscore` внутри нашего jar.

## ADR-24 · Сначала рабочий путь с книгой из FTB
Решение автора: как можно раньше увидеть квесты RepYS в игре. После M1 делаются минимальные версии M2, M3 и M6, из M5 берутся только типы, которые есть в книге (`stat`, `kill`, `visit`, награда `random`). Остальное из этих этапов и M4, M7, M8 идёт после проверки автором. Синхронизация с FTB это повторный запуск `/rysquests import ftbq`: результат пишется в автоматически подключаемый пак `config/rysquests/import/`, а `ftbq-ids.json` хранит соответствие id, поэтому повторный импорт их не меняет. Прогресс переносится отдельной командой из `world/ftbquests/`. Отвергнуто: постоянная двусторонняя связь с FTB Quests.

## ADR-25 · Решения, принятые при доводке книги
- Скрытые квесты (`hidden`) приходят клиенту и скрываются в интерфейсе, пока не откроются. Причина: книга отправляется целиком (ADR-8), а рассылать её заново при каждом открытии дороже, чем скрывать. Это оформление, а не защита от чтения данных.
- Раскладка карты считается в фоне и живёт в памяти, на диск не пишется: 2000 узлов укладываются быстрее 200 мс. Отменяет кэш на диске из ADR-7.
- В команде задачи общие, а награды каждый получает сам. С `team_mode: once` награду забирает первый, остальным она засчитывается.
- Закрепление на `P`: `A` и `G` над предметом перехватывает RYScope.
- Вид следует правилам RYSCore 1.2: разделы через `tabLine`, янтарь только у главного действия окна.

## ADR-26 · Команды через `TeamsApi`
В режиме `team` команду определяет `TeamsApi` из RYSCore. Если мода команд нет, работают наши `/rysquests team`. При слиянии и выходе прогресс переносит `TeamBridge`. Дополняет ADR-4.

## ADR-27 · Интерфейс совпадает с макетами
Просьба автора: «Юай должен совпадать с дизайном точно». Экраны считаются в пикселях макета через `Ui`, при окне 1280×800 и GUI Scale 2 они совпадают с `design/*.dc.html`. Заменяет перевод единиц из ADR-18, правила шапки и подсказок из ADR-19 и последний пункт ADR-25: где макет и правила кора расходятся, главнее макет.

Отступления от макетов, без которых нельзя:
- В шапке после вкладок макета стоит «Поток» и для операторов «Dev». В макете Main нет пути назад в Поток.
- Иконки и слоты остаются квадратными: в макете часть из них браузер сжал на несколько пикселей.
- Цвета только из токенов темы, поэтому в Потоке есть расхождения на 1–3 уровня от `#1e2029` и других значений.
- Пока нет данных: медиана времени в воронке, кто из команды что сделал. Эти места пусты или показывают прогресс своей команды.

## ADR-28 · Что снято с MVP
Решение автора. Этого нет в макетах, а по `10-design-rules.md` чего нет в макетах, того нет и в интерфейсе.
- Плотность интерфейса: противоречит точному совпадению с макетом.
- Перетаскивание доски стикеров: её положение по высоте задаёт `boardTop` в клиентском конфиге.
- Перенос `quest_links` из FTB: повтор квеста на другой странице потребовал бы нового поля и вида на карте. Импорт по-прежнему перечисляет такие ссылки в `import-report.md`.

## ADR-29 · Гайды простые
Решение автора: гайды в S1 как в макетах, страница это текст, картинки и ссылки. Маршрут по моду, шаги с условиями и 3D-структуры из `09-sections.md` не делаем.
