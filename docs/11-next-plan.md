# 11 · План после MVP (актуальный)

Дата: 2026-11-10. Составлен чатом дизайна по состоянию репозитория: `CHANGELOG.md`, `05-plan.md`, журнал коммитов, ADR до 31-го. Этот файл самодостаточен: по нему можно работать, даже если предыдущая переписка потеряна. Подробности лежат в файлах, на которые он ссылается, и все они есть в папке.

## Где мы сейчас

Сделано и проверено автотестом на копии RepYS: M0–M8 из `05-plan.md`. Книга грузится из датапаков, есть прогресс, сдача, награды, виды Поток, Карта, Что дальше, Список, Лента, стикеры, поиск, миграции, команды через `TeamsApi`, стадии, импорт из FTB Quests, мост к JEI и RYScope, вкладка Dev с отчётами, плагин KubeJS.

Из задач дизайна уже выполнено:

- поле `section` у главы, книга показывает только `story` (коммит «Add the section field…»);
- вкладки видов нарисованы текстом с линией (ADR-30);
- экраны переведены на масштаб RYSCore 1.6 (ADR-31);
- гайды зафиксированы простыми (ADR-29).

Работа с установленным RYSTeams проверена на выделенном сервере с двумя клиентами (`tools/team-autotest.ps1 -RysTeams`).

Сделаны S1, S2 и S3: рейка разделов, гайды и кастомные вкладки для игрока, редактор гайдов и страниц (ADR-35). Не сделано: конструктор вкладок, магазин, достижения, редактор квестов.

## Суть разделов в шести строках

- У книги слева **рейка разделов** 84 пикселя макета (42 единицы GUI). Состав задаёт `book.json`.
- **Встроенные** разделы: Сюжет (уже есть), Гайды, Магазин, Достижения.
- **Кастомные вкладки** автор сборки собирает сам из трёх шаблонов: Матрица, Карточки, Страницы.
- **Атлас добычи** (ресурс × стадия: ранняя, средняя, поздняя) и **Атлас сборки** (направления × эпохи) это кастомные вкладки на Матрице. Мод ничего не читает из генерации мира.
- **Гайд** это название, иконка и страницы. Страница это заголовок и текст со вставками: предмет, рецепт, картинка, ссылка. Панель «Квесты по теме» и «Предметы на странице» собирается сама.
- **Страницы** как шаблон заменяют Patchouli и используют тот же формат и тот же редактор, что гайды.

## Этапы

Порядок выбран так, чтобы после каждого этапа автор сборки уже мог пользоваться результатом, заполняя JSON руками. Редакторы идут после видов игрока.

### P0 · Сверка (меньше сессии)

- Прочитать файлы из таблицы выше. Сверить `09-sections.md` с ADR-29–31 и текущим кодом; расхождения выписать автору списком.
- Проверить книгу с установленным RYSTeams на выделенном сервере (долг из `05-plan.md`).
- Заменить в интерфейсе символы вне набора значков кора на значки (шеврон, ручка перетаскивания, карандаш, отмена, повтор, точка).

Приёмка: список расхождений у автора; автотест с RYSTeams зелёный; в интерфейсе нет символов, падающих на шрифт игры.

### S1 · Рейка разделов и Гайды для игрока (2–3 сессии)

- `book.json`: список `sections`. Без него рейка скрыта, как сейчас.
- Рейка разделов в `BookScreen`: выбранный пункт с заливкой (это пункт списка, а не вкладка). Рейка глав Потока остаётся внутри раздела Сюжет (ADR-32).
- Загрузчик гайдов: `data/<ns>/rysquests/guides/<id>.json`, один файл на гайд, тексты в lang. Формат в `09-sections.md`, раздел «Гайды».
- Вставки в тексте: `[[item:]]`, `[[recipe:]]`, `[[image:]]`, `[[quest:]]`, `[[guide:]]`, жирный. Разбор расширяет существующий парсер разметки.
- Библиотека (`Guides.dc.html`): карточки, чипы категорий, состояния «нужен сейчас», «прочитан», «закрыт до стадии».
- Гайд изнутри (`GuidePage.dc.html`): список страниц с отметкой прочитанного, страница, правая панель из двух авто-блоков.
- Поле `guide` у квеста и кнопка «Как это работает» в карточке.
- Прочитанность страниц в `ProgressStore`, синхронизация диффом.
- Валидатор: несуществующий гайд, предмет, квест, ключ lang, файл картинки.
- Пример гайда в `examples/`.

Тесты: кодек гайда, парсер вставок, сбор «Предметы на странице», подбор «Квесты по теме».

Приёмка: в тестовом мире гайд из примера открывается с рейки, страницы листаются, отметка прочитанного сохраняется, кнопка из квеста ведёт на нужную страницу, клик по предмету открывает рецепт. Снимки рядом с макетами.

### S2 · Кастомные вкладки для игрока (3 сессии)

- Загрузчик `data/<ns>/rysquests/sections/<id>.json` с полем `template`.
- **Матрица** (`Mining.dc.html`, `Atlas.dc.html`): строки, столбцы с привязкой к стадии, ячейки со способами, панель выбранной ячейки, поиск, группы, `spoilers`.
- **Карточки** (`Cards.dc.html`): сетка, фильтры, условие отметки, страница карточки справа.
- **Страницы**: тот же вид, что у гайда изнутри, без библиотеки.
- Закрепление способа на HUD через существующий `StickerBoard`.
- Валидатор и примеры всех трёх шаблонов в `examples/`.

Приёмка: три примера вкладок видны на рейке и работают; текущий столбец Матрицы подсвечивается по стадии игрока; файл вкладки можно править руками и видеть результат после `/rysquests reload`.

### S3 · Редактор: основа и страницы (3 сессии)

Редактора в игре пока нет совсем, поэтому этап начинается с общей основы.

- Оболочка dev-режима (`Editor.dc.html`, шапка с бейджем «Редактор»): вход только с правами, отмена и повтор, счётчик изменённых файлов, «Сохранить в датапак», горячая перезагрузка.
- **Перед кодом проверить и согласовать с автором**: куда редактор пишет файлы (датапак мира, папка `config`, папка разработки) и как это работает на выделенном сервере. Оформить ADR.
- Редактор гайда и шаблона «Страницы» (`PageEditor.dc.html`): список страниц, заголовок, текст, кнопки вставок, справа предпросмотр.
- «+ Предмет» из руки и перетаскиванием. «+ Картинка»: **проверить перед кодом**, как забрать скриншот и положить в ресурсы пака; если не получается, оставить выбор файла из папки.

Приёмка: автор создаёт гайд из двух страниц с предметом, рецептом и картинкой, не выходя из игры, и после сохранения файл совпадает с форматом из S1.

### S4 · Редактор: конструктор вкладок (2–3 сессии)

- `SectionEditor.dc.html`: список пунктов рейки с порядком, «Новая вкладка из шаблона», таблица Матрицы в режиме правки, свойства способа, строки и вкладки, замечания проверки, «Глазами игрока».
- Редактор шаблона «Карточки» на тех же деталях.

Приёмка: автор собирает Атлас добычи на пять ресурсов и три стадии целиком в игре.

### S5 · Валюта и Магазин (3 сессии)

- Валюта: число на сервере в `ProgressStore`, тип награды `currency`.
- **Сначала решить с автором**: валюта и титулы живут в RYSQuests или в RYSCore (открытый вопрос).
- Сделки: покупка и продажа, лимиты на игрока и команду, сброс, история. Сервер авторитетен.
- Экран `Shop.dc.html`. Dev-отчёт о цепочках сделок с положительным циклом.

Приёмка: покупка и продажа работают на выделенном сервере с двумя игроками, лимит нельзя обойти перезаходом, отчёт ловит намеренно сломанную пару сделок.

### S6 · Достижения (2 сессии)

- Запись достижения с уровнями и наградами `currency` и `title`, скрытые, редкость по серверу с кэшем.
- **Проверить перед кодом** источники счётчиков для каждого типа задачи.
- Экран `Achievements.dc.html`, закрепление на HUD.

Приёмка: три достижения из примера получают уровни в тестовом мире, скрытое раскрывается при получении, редкость считается на сервере.

### S7 · Редактор квестов (3–4 сессии)

- Карта в режиме правки по `Editor.dc.html`: создание квеста, зависимости перетаскиванием, свойства, задачи и награды, авто-раскладка, подсветка внешних изменений.

Приёмка: автор создаёт главу из десяти квестов с зависимостями в игре, файлы совпадают с форматом `02-data-format.md`.

## Правила дизайна, которые действуют на каждом экране

Полностью в `10-design-rules.md`. Коротко, с поправками после проверки в игре:

- Макет это эталон. 1 единица GUI равна 2 пикселям макета. Масштаб окон по ADR-31.
- Цвета, шрифты, скругления только из темы. Литералов в коде экранов нет.
- Акцент значит одно: активно, выбрано, главное действие. Залитая акцентом кнопка на экране одна.
- Вкладка это текст с линией, подпись в одну строку. Заливка только у кнопок, чипов и выбранного пункта списка (рейка).
- Состояние никогда не передаётся только цветом.
- Символов вне набора значков кора нет.
- Если в строке есть кириллица, вся строка рисуется Inter 600.
- Действия в строках списков значками, не текстовыми кнопками.
- Правый верх экрана занят картой: постоянные элементы туда не ставить.
- Отступление от макета: сказать автору до кода, записать ADR, обновить эталон.
- Сдача экрана: снимки в темах Slate и Glass на 2560×1440 и 1920×1080 рядом с макетом.

## Что отброшено, не возвращать

- «Карта руд» с чтением высот из генерации мира (`_stale/Ores.dc.html`).
- Сложные гайды: маршрут по моду, блоки, шаги с условиями, 3D-структуры (ADR-29).
- Плотность, перетаскивание доски стикеров, перенос `quest_links` (ADR-28).
- Концепт «Компаньон». Тема Create отложена.

## Процесс

- Один этап за раз, приёмка перед переходом, запись в `CHANGELOG.md`.
- Прогресс списком сверху, сделанное помечать ✅. Перед этапом коротко изложить план.
- Не выдумывать API: сказать «проверю» и проверить по исходникам.
- Ничего не удалять, ненужное в `_stale`. Момент коммита и пуша выбирает Claude (решение автора, как в `CLAUDE.md`).
- Тесты в игре только в отдельном тестовом мире.
- Изменения формата сопровождать записью в `02-data-format.md` и примером в `examples/`.
