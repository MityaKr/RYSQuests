# 06 · Ограничения среды и тестирование

## Среда автора

- Windows, ПК `mityays`. Папка проекта `C:\Projects\RepYS\RYSQuests`.
- Рядом инстансы RepYS (CurseForge app): dev `RepYS`, игровой `RepYS - Engine of Creation`, сервер `RepYS-2.2.0-server`. Для разработки свой `run/` через ModDevGradle.
- `Instances/RepYS` (дев-площадка сборки, 364 мода) не менять, для тестов делать копию. `Instances/For-Into-Mod` можно менять, но там же тестируется RYScope: перед заменой jar переносить старый в `_stale`. Запущенная игра автора не повод ждать.
- Папка `C:\Projects\RepYS\RYScope` только для чтения: не менять, не коммитить, не запускать сборку, не трогать `prodtest/run-repys`. Рабочее дерево может быть в середине правок, стабильное состояние в `main`. Нужна правка в RYScope: написать автору блок «Запрос к RYScope» (что, зачем, какой контракт).
- Файлы не удалять (`rm` запрещён). Ненужное в `_stale/`.
- Доступ к управлению компьютером разрешён; правый монитор не трогать.
- Генератор книги RepYS на Python в `_dev/gen` (другая папка, по запросу автора). Импортёр и формат должны быть удобны для него: один файл на квест, стабильный порядок полей, строковые id из названий.

## Сборка

- Maven NeoForge (`maven.neoforged.net`) был недоступен из облачной среды и с ПК автора в предыдущих сессиях. Первое действие M0: проверить. Если недоступен, варианты: оффлайн-кэш Gradle, собранный в другой сети; зеркало; разовое скачивание зависимостей. Решает автор.
- ModDevGradle предпочтительнее NeoGradle: проще, быстрее, даёт декомпилированные исходники Minecraft и NeoForge для чтения API. Если с ним проблемы, запасной вариант NeoGradle 7.
- Версии фиксировать в `gradle.properties`. Актуальную `neo_version` для 1.21.1 брать из maven, не из памяти.
- Декомпиляция сторонних модов для изучения: CFR (`cfr.jar` из Maven Central), результат в `_stale/decompiled/` или вне репозитория.

## Что нельзя предполагать

- Сигнатуры API NeoForge 21.1 (события, payload'ы, SavedData, reload listeners, KeyMapping) проверять по исходникам в IDE/декомпиляции перед использованием. Названия методов менялись между 1.20 и 1.21.
- Формат файлов FTB Quests для 1.21.1 проверять по исходникам FTB Quests и реальному экспорту из RepYS.
- API JEI для 1.21.1 проверять по его jar.

## Тестирование

- JUnit 5: кодеки, граф, валидатор, раскладка, миграции, импортёр, парсер разметки. Запуск `./gradlew test`.
- В игре: `./gradlew runClient`, отдельный новый мир в `run/saves/`, не удалять, переиспользовать. Для сети `runServer` + клиент, или LAN.
- Автотест: `./gradlew runAutotest` сам создаёт мир, нажимает клавиши и мышь, снимает скриншоты и выходит (M0.1).
- Проверка на копии RepYS «как у игрока» по образцу `prodtest/build.gradle` RYScope: большая сборка подключается папкой `mods`, не через classpath (иначе Sodium не находится), игровые тесты NeoForge выключены (иначе падает Binnie Core). В больших сборках поведение сверять на RepYS, а не только на чистой игре.
- Логи `run/logs/latest.log` читать после каждого запуска, ошибки и предупреждения мода разбирать.
- Производительность: `spark` или встроенный профайлер при проверке целей M8.
