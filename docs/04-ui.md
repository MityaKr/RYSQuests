# 04 · Интерфейс

Референс визуала: `design/Main.dc.html` (карта + карточка), `design/Comfort.dc.html` («Поток»), `design/Home.dc.html` («Что дальше»), `design/Hud.dc.html` (стикеры), `design/List.dc.html`, `design/Timeline.dc.html`, `design/Dev.dc.html`. Макеты 1280×800 это окно книги 1200×728 в экране. В игре окно занимает те же доли экрана (93,75 % ширины, 91 % высоты), поэтому при окне 1280×800 и GUI Scale 2 оно совпадает с макетом пиксель в пиксель.

Единицы (ADR-27): код экранов работает в пикселях макета через `client.screen.Ui`, числа берутся из макетов без пересчёта. Один пиксель GUI при масштабе 2 это два пикселя макета.

## Общая структура экрана книги

```
┌ логотип · вкладки · поиск · команда · закрыть ───────────────────────────────┐
│ ┌ главы (232) ┐ ┌ карта ──────────────────────────────┐ ┌ карточка (392) ┐ │
│ │ список с    │ │                                     │ │ квест:         │ │
│ │ прогрессом  │ │                                     │ │ задачи, награды│ │
│ └─────────────┘ └─────────────────────────────────────┘ └────────────────┘ │
└──────────────────────────────────────────────────────────────────────────────┘
```

Так выглядят Карта и Список (у Списка нет карточки). Что дальше, Лента и Dev занимают всё место под шапкой. Поток это другая рамка, как в `Comfort.dc.html`: рейка глав с римскими номерами, колонка ленты, колонка чтения. В окне уже 1000 пикселей макета карточка у карты не показывается.

## Виды (MVP: Поток и Карта; затем Что дальше, Список)

**Поток** (по умолчанию для глав без сильного ветвления): вертикальная лента. Сверху свёрнутая строка «Выполнено N из M», затем доступные и активные квесты по порядку топологической сортировки, текущий раскрыт на месте (задачи, кнопка «Сдать», награда), ветвления как блок «Дальше, на выбор» из 2–3 карточек, остаток за ссылкой «ещё N впереди». Клавиши: ↑↓ перемещение, Enter раскрыть, G сдать. Раскрытый квест и есть его карточка, справа колонка чтения: как сделать, рецепт, почему дальше закрыто. При раскрытии верх строки закреплён, содержимое растёт вниз.

**Карта**: граф главы на точечной сетке 24 px, автораскладка (см. ниже), группы-подглавы пунктирной рамкой с заголовком, выполненные ветки свёрнуты в один узел «✓ свёрнуто N», мини-карта в углу, Shift+колесо масштаб, перетаскивание ЛКМ по фону, F фокус на пути к выбранному квесту. Рендер только видимых узлов и рёбер.

**Что дальше** (M8): три рекомендации (доступен, ближе к завершению, ведёт к следующей главе), награды к получению, прогресс глав, лента эпох.

**Список** (M8): группы по статусу, строка с действием.

## Карточка квеста

Заголовок с иконкой, подзаголовок «глава · требует · открывает», кнопка закрепить. Табы: Задачи (по умолчанию), Текст, Награды сгруппированы под задачами. Строка задачи: чекбокс состояния, иконка, текст, прогресс `n / m`, кнопка «Сдать» для consume. Награды: слоты, «выберите 1 из N» с акцентной рамкой на выбранной. Текст с разметкой; рецепт нужного предмета через `RecipeViewerBridge`, если доступен. Низ: «Зависимости», «Ссылка в чат» (вставляет `[[quest:id]]` в чат как компонент с кликом).

## HUD-стикеры

Закреплённый квест это стикер на нашем `client.hud.StickerBoard`, как в `design/Hud.dc.html`: доска справа сверху, ширина 300 пикселей макета, отступ 20, клавиша B сворачивает. Контракт стикера: id, высота, отрисовка, приоритет. Отступ сверху задаётся настройкой `boardTop` в клиентском конфиге: в сборке с миникартой в этом углу доску можно опустить ниже неё. Прячется, когда открыт любой экран, и в бою (конфиг). При завершении квеста на доске пять секунд видна карточка «Квест выполнен · награда ждёт в книге · K».

## Поведение окон (ADR-19)

- Окно открывается сразу. Тяжёлый расчёт идёт вне кадра или порциями, внутри окна индикатор `Loading`.
- Окна не прыгают: верхний край закреплён, рост только вниз.
- Подсказки по клавишам внизу экранов такие, как в макетах.
- Шапка без лишнего: предмет и название не повторяются, если они уже видны.
- Вкладки вместо стрелок «1/7» там, где страниц несколько.
- Вкладки видов книги: текст с линией под активной, без заливки (ADR-30). Заливка у вкладок только в Dev, как в его макете. Переключатели сортировки в Списке это фильтры, у них заливка остаётся.
- Панели обходят чужие области экрана, а не перекрывают их.
- Макеты этой папки главнее правил кора (ADR-27). Цвета только через токены: то, чего нет в теме, смешивается из токенов в `Ui`. Сверка: снимок игры 1280×800 при GUI Scale 2 накладывается на макет в режиме разницы (`runAutotest -Pautotest=design`, книга с содержимым макетов лежит в `src/autotest/design_pack`).
- `BookScreen` это обычный `Screen`, а не `AbstractContainerScreen`: панели RYScope на нём не рисуются. Окно рецептов RYScope открывается поверх и возвращается в книгу как в родителя, поэтому книга сохраняет скролл и выбранный квест.

## Клавиши

| Клавиша | Действие |
|---|---|
| K | открыть книгу на текущем квесте / закрыть |
| G | сдать всё готовое по закреплённым и текущему (с тостом-сводкой) |
| P | закрепить/снять выбранный квест (в книге) |
| B | свернуть доску стикеров |
| Esc | закрыть |
| Ctrl+F | поиск в книге |

Все переназначаемые через стандартные `KeyMapping`.

Известные конфликты значений по умолчанию (что с ними делать, решает автор):

- RYScope на экранах других модов перехватывает `A` (закладка) и `G` (дерево крафта) раньше нашего экрана, но только над предметом, о котором экран сообщил JEI.
- В сборке RepYS на `K` уже 5 привязок, включая шейдеры Iris; на `G` 10, включая Curios и GuideME.

## Темы (RYSCore)

Темами занимается RYSCore (ADR-23): `assets/<ns>/ryscore_themes/<имя>.json`, встроенные `ryscore:slate` (по умолчанию), `ryscore:vanilla`, `ryscore:glass`. Выбор темы один на все моды семьи, книга берёт его через `ThemeManager.get()` и своей настройки темы не имеет. Перезагрузкой тем занимается кор.

Поля файла темы: `name`, `font`, `colors`, `metrics`, `effects`.

```json
{
  "name": "Slate",
  "font": "minecraft:default",
  "colors": {
    "overlay": "#0e1016", "overlay.alpha": 0.55,
    "panel.bg": "#1c1f27", "panel.border": "#2c313d", "sidebar.bg": "#16181f",
    "card.bg": "#20242e", "card.border": "#343a48",
    "slot.bg": "#12141a", "slot.border": "#262a35", "slot.hover": "#2a2f3b",
    "text.primary": "#f7f8fb", "text.body": "#e6e8ee", "text.muted": "#8b93a5", "text.dim": "#5f6678",
    "accent": "#e4b23c", "accent.text": "#15181f",
    "state.ok": "#6fcf8f", "state.warn": "#e4b23c", "state.bad": "#e36b6b"
  },
  "metrics": { "panel.radius": 12, "card.radius": 14, "slot.radius": 6, "button.radius": 9, "bevel": 0, "slot.size": 18, "slot.gap": 3, "missing.alpha": 0.45 },
  "effects": { "blur": 0, "shadow": true, "animations": "normal" }
}
```

Здесь показана часть из 36 токенов Slate; полный список в файле темы. Vanilla вместо рамок задаёт бевели (`panel.bevel.light`, `slot.bevel.dark` и другие), Glass добавляет `tab.style: pill` в `metrics`. Незаданный токен берётся по цепочке запасных из `Theme`, а токен без запасного рисуется маджентой.

Радиусы в `metrics` заданы в единицах макета, `Theme.r()` переводит их в GUI. Рисование только через `Draw` и примитивы `Theme`, цвета только через токены, констант в экранах нет.

Своих токенов не вводим, состояния квестов выводятся из существующих:

| Что | Токен |
|---|---|
| Узел выполнен | рамка и текст `state.ok` |
| Активный узел | рамка `text.muted`, выбранный `text.primary` |
| Закрытый узел | текст `text.dim`, значок `Draw.lock` |
| Рёбра | `state.ok` / `text.muted` / `panel.border` |
| Фон карты и точки сетки | `sidebar.bg` и `slot.border` |
| Информационный цвет | `chip.mod.fg` (токена `state.info` нет) |

## Виджеты (MVP)

`Panel`, `Slot` (предмет, количество, шанс, подсветка состояния), `ProgressBar`, `Button` (с клавишной подписью), `Tabs`, `ScrollList` (виртуализованный: создаёт виджеты только для видимых строк), `Tooltip`, `TextBlock` (разметка). Они живут в `works.repka.rysquests.client.widget`, пока не понадобятся второму моду; индикатор `Loading` берём из RYSCore. Все виджеты берут цвета и метрики из активной темы, а не из констант.

## Автораскладка (клиент, `layout`)

1. Узлы главы минус свёрнутые выполненные ветки.
2. Слои: длиннейший путь от корней (квесты без зависимостей внутри главы). Фиксированные узлы (`layout.x/y`) закрепляются за слоем по x.
3. Порядок в слое: барицентр соседей, 4 прохода вниз-вверх, стабильная сортировка.
4. Координаты: слой → колонка (ширина узла 132–200 px + 48 px), позиция в слое → строка (высота 40–56 px + 24 px), выравнивание по сетке 24.
5. Рёбра ортогональные: горизонталь → вертикаль → горизонталь, с общим вертикальным сегментом на полпути между слоями.
6. Результат кэшируется по `(bookHash, chapterId, collapsedSetHash)` в `config/rysquests/layout-cache/`.

Считается в фоне, во время расчёта показывается предыдущая раскладка или индикатор `Loading`.

## Доступность

Все действия доступны с клавиатуры; фокус виден (рамка accent). Состояние узла дублируется текстом и формой, не только цветом. Минимальные цели клика 20 px в GUI-пикселях (в масштабе 2 это 40 px экрана).
