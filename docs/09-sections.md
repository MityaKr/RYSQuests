# 09 · Разделы книги и кастомные вкладки

Статус: **дизайн-предложение, после MVP**. В M1 закладывается только поле `section` у главы, всё остальное делается этапами S1–S5 после M8.

Этот документ написан так, чтобы его можно было прочитать без истории переписки: сначала словарь, потом каждый раздел, потом формат данных и порядок работ. Правила внешнего вида вынесены в `10-design-rules.md`, они обязательны.

## Словарь: что чем является

| Термин | Что это |
|---|---|
| **RYS** | Семейство отдельных модов автора (не часть сборки RepYS): RYScope, RYSQuests, RYScore; RYSPulse и RYSTeams в виде концептов. |
| **RYSQuests** | Мод квестов, замена FTB Quests. Этот репозиторий. |
| **RYScope** | Мод просмотра рецептов, замена JEI/EMI. Отдельный проект. |
| **RYScore** | Общая UI-библиотека семейства: темы, виджеты, HUD-доска, разметка ссылок. |
| **Книга** | Весь контент квестов одного пака: `data/<ns>/rysquests/`. |
| **Раздел** | Пункт рейки слева в окне книги. У раздела свой экран. Бывает встроенным или кастомным. |
| **Рейка** | Узкая колонка 84 px с иконками разделов. Состав и порядок задаёт автор пака. |
| **Встроенный раздел** | Раздел с собственной логикой в коде мода: Сюжет, Гайды, Магазин, Достижения. |
| **Кастомная вкладка** | Раздел без своей логики: автор пака собирает его сам из шаблона в dev-режиме. Примеры: Атлас сборки, Атлас добычи. |
| **Шаблон** | Готовая раскладка для кастомной вкладки. Их три: «Матрица», «Карточки», «Страницы». |
| **Матрица** | Шаблон «строки × столбцы». Столбец можно привязать к стадии, тогда текущий подсвечивается сам. |
| **Карточки** | Шаблон-каталог: сетка карточек с фильтрами. Карточка может открывать страницу. |
| **Страницы** | Шаблон-книга: разделы, страницы, блоки. Замена Patchouli. |
| **Блок** | Кусок страницы одного типа: текст, шаги, структура, рецепт и т.д. Общий для гайдов и шаблона «Страницы». |
| **Маршрут** | Полоса шагов наверху гайда: в каком порядке проходить мод и где игрок сейчас. |
| **Способ** | Одна запись в ячейке Матрицы: иконка, название, описание, что нужно, ссылки. |
| **Стадия** | Этап прогрессии игрока или команды (StageProvider, см. 03-api). В сборке автора это эпохи. |
| **Dev-режим** | Режим автора пака: редактор квестов, конструктор вкладок, отчёты, миграции. Игрокам недоступен. |
| **Slate** | Тема по умолчанию и эталон дизайна. |

## Зачем разделы

В FTB Quests магазин, ачивки, справочники и гайды по модам делают обычными главами. Получается лента из 40–60 глав, где сюжет перемешан со справкой, а «магазин» это квесты с галочкой.

В RYSQuests сюжет остаётся чистым, а всё остальное живёт в своих разделах.

| Раздел | id | Вид | Что это | Этап |
|---|---|---|---|---|
| Сюжет | `story` | встроенный | главы прогрессии (Поток, Карта, Список, Лента) | MVP |
| Гайды | `guides` | встроенный | библиотека справочных глав по модам | S1 |
| Атлас сборки | свой id | кастомная, Матрица | направления × эпохи: какие моды где в сборке | S2 |
| Атлас добычи | свой id | кастомная, Матрица | ресурс × стадия игры: откуда брать ресурс на ранней, средней и поздней стадии | S2 |
| Магазин | `shop` | встроенный | покупка и продажа за валюту | S4 |
| Достижения | `achievements` | встроенный | достижения с уровнями | S5 |

Раздел без содержимого на рейке не показывается.

## Кастомные вкладки (S2)

Главная идея: **мод ничего не знает о рудах, эпохах и модах сборки**. Он даёт шаблон и редактор, а содержимое собирает автор пака. Никаких данных из генерации мира, никаких вычислений: что автор написал, то игрок и видит.

### Шаблон «Матрица»

- Строки: что угодно (ресурсы, направления, моды). У строки иконка, название, группа для фильтра.
- Столбцы: что угодно, обычно стадии. У столбца название, подпись и необязательная привязка `stage`.
- Ячейка: список способов (ноль и больше).
- Способ: иконка, название, пометка (`auto`, `manual` или нет), флаг «лучший на стадии», описание с разметкой ссылок, список «что нужно» (предметы), ссылки на квест, рецепт, гайд.

Поведение у игрока:

- текущим считается последний столбец, стадия которого открыта; он подсвечен акцентом, пройденные слегка приглушены, закрытые приглушены сильнее;
- автор решает, показывать ли закрытые столбцы (`spoilers: show | dim | hide`), по умолчанию `dim`;
- клик по ячейке открывает справа панель со всеми способами этой ячейки и строкой «Дальше»;
- поиск по строкам и чипы групп сверху;
- способ можно закрепить стикером на HUD;
- ссылка `recipe` открывает рецепт через RecipeViewerBridge, `quest` и `guide` переводят внутри книги.

### Атлас добычи

Кастомная вкладка на Матрице. Строки это ресурсы, столбцы это три стадии игры: **ранняя, средняя, поздняя**. В ячейке способы добычи ресурса на этой стадии. Макет: `design/Mining.dc.html`.

Пример игрока: «Железо, средняя стадия: дробление руды (лучший), промывка гравия (авто). Дальше: ферма големов, с эпохи VI».

Содержимое макета условное, реальные способы пишет автор сборки.

### Атлас сборки

Та же Матрица: строки это направления (Техника, Энергия, Хранение, Магия, Природа, Финал), столбцы это эпохи, способ в ячейке это мод. Макет: `design/Atlas.dc.html`.

### Формат

Один файл на вкладку: `data/<ns>/rysquests/sections/<id>.json`.

```json
{
  "template": "matrix",
  "title": "section.repys.mining_atlas",
  "icon": "minecraft:iron_pickaxe",
  "spoilers": "dim",
  "groups": ["metal", "gem", "fluid"],
  "columns": [
    { "id": "early", "title": "section.repys.mining_atlas.early" },
    { "id": "mid",   "title": "section.repys.mining_atlas.mid",  "stage": "repys:epoch_3" },
    { "id": "late",  "title": "section.repys.mining_atlas.late", "stage": "repys:epoch_6" }
  ],
  "rows": [
    {
      "id": "iron", "icon": "minecraft:iron_ingot", "group": "metal",
      "cells": {
        "mid": [
          {
            "id": "crushing", "icon": "create:crushing_wheel", "mark": "manual", "best": true,
            "needs": ["create:crushing_wheel", "create:shaft"],
            "links": [
              { "type": "quest",  "id": "repys:industry/crushing" },
              { "type": "recipe", "id": "create:crushed_raw_iron" },
              { "type": "guide",  "id": "create/crushing" }
            ]
          }
        ]
      }
    }
  ]
}
```

Тексты способа берутся из lang по ключу `<title вкладки>.<row>.<column>.<way>.name` и `.text`. Id строк и способов строковые и стабильные, как у квестов. Прогресса у кастомной вкладки нет, на сервере она ничего не хранит: файл уходит клиенту вместе с книгой.

### Шаблон «Карточки»

Каталог: сетка карточек с фильтрами и поиском. Макет: `design/Cards.dc.html` (пример «Боссы»).

- Карточка: иконка, фон, название, строка описания, метка (например измерение), группа для фильтра, необязательные `stage` (закрыта до стадии) и `done` (условие отметки, тот же тип, что задача квеста).
- Справа панель выбранной карточки: описание и короткий набор блоков.
- Кнопка «Открыть страницу»: полная страница из тех же блоков, что у гайдов.

```json
{
  "template": "cards",
  "title": "section.repys.bosses",
  "icon": "minecraft:wither_skeleton_skull",
  "groups": ["overworld", "nether", "end", "modded"],
  "cards": [
    { "id": "wither", "icon": "minecraft:nether_star", "group": "nether",
      "done": { "type": "kill", "entity": "minecraft:wither" },
      "page": "repys:bosses/wither" }
  ]
}
```

### Шаблон «Страницы»

Книга: разделы, страницы, блоки. **Это замена Patchouli** внутри книги квестов. Вид игрока тот же, что у гайда изнутри, только без маршрута и панели «Куда двигаться» (их можно включить в настройках вкладки). Формат страниц и редактор те же, что у гайдов, файлы лежат в `sections/<id>/`. Подходит для правил сервера, лора, списка изменений, справочника по сборке.

Гайды это по сути встроенная вкладка на «Страницах» с тремя добавками: маршрут, связь с квестами, библиотека по модам.

### Конструктор в dev-режиме

Макет: `design/SectionEditor.dc.html`. Это тот же редактор, что для квестов (`Editor.dc.html`), с той же шапкой и теми же правилами сохранения.

- **Слева**: список пунктов рейки с перетаскиванием для порядка и пометкой «встроен» или «своя»; ниже «Новая вкладка из шаблона» (Матрица, Карточки, Страницы).
- **В центре**: та же таблица, что видит игрок, в режиме правки. Столбцы и строки перетаскиваются за ручку, у столбца видна привязка к стадии. В каждой ячейке пунктирный слот «+ способ». Новую строку можно создать, перетащив предмет из инвентаря или из RYScope.
- **Справа**: свойства выбранного, вкладки «Способ», «Строка», «Вкладка», «JSON».
- **Внизу**: замечания проверки. Минимум: пустая ячейка, несуществующий предмет, ссылка на несуществующий квест или гайд, строка без единого способа, отсутствующий ключ lang.
- Кнопка **«Глазами игрока»** показывает вкладку так, как её увидит игрок на выбранной стадии.
- «Сохранить в датапак» пишет тот же JSON, что можно править руками. Отмена и повтор, горячая перезагрузка, как в редакторе квестов.

## Гайды (S1)

Задача гайда: **показать игроку, куда и как двигаться**, а не просто дать текст. Поэтому гайд это маршрут плюс страницы из блоков. Макеты: `design/Guides.dc.html` (библиотека), `design/GuidePage.dc.html` (гайд изнутри), `design/PageEditor.dc.html` (редактор).

### Библиотека

- карточки модов: иконка, название, прочитано страниц, чипы категорий;
- состояния: «нужен сейчас», «прочитан», «закрыт до эпохи N»;
- плашка «Для твоего квеста»: гайд, на который ссылается закреплённый квест.

### Гайд изнутри

- **Маршрут** сверху: шаги по моду слева направо (Андезит → Вращение → Обработка → …). Состояния: пройдено, «ты здесь», впереди, закрыто стадией. Шаг маршрута это раздел гайда; «пройдено» считается по привязанным квестам, а если их нет, по прочитанным страницам.
- **Оглавление** слева: страницы текущего раздела с галочками прочитанного, ниже остальные разделы.
- **Страница** в центре: блоки сверху вниз.
- **«Куда двигаться»** справа:
  - твой квест по этой теме с прогрессом и кнопкой «К квесту»;
  - «Понадобится»: предметы страницы и сколько их уже есть (и у кого в команде);
  - «Это откроет»: что станет доступно после;
  - «Если застрял»: короткие вопросы с ответами;
  - «Закрепить шаги на HUD».

### Блоки страницы

| Блок | Что показывает |
|---|---|
| `text` | абзац с разметкой ссылок `[[item:]]`, `[[quest:]]`, `[[guide:]]` |
| `steps` | нумерованные шаги; у шага предмет и необязательное условие «сделано» (тот же тип, что задача квеста) |
| `structure` | модель постройки: вращение, показ по слоям, список блоков, «Показать в мире» (призрак на месте) |
| `recipe` | рецепт предмета, рисуется через RecipeViewerBridge, ссылка «открыть во вьюере» |
| `item` | предмет крупно с подписью |
| `image` | картинка из ресурсов |
| `tip` | плашка «Совет» (info) или «Важно» (bad) |
| `entity` | модель моба |
| `quest` | карточка квеста с прогрессом |
| `links` | «куда дальше»: страницы, квесты, вкладки |

У любого блока есть условие показа (`when`: стадия или квест), чтобы не спойлерить.

### Формат

`data/<ns>/rysquests/guides/<guide>/_guide.json` (название, иконка, мод, категории, маршрут), разделы подпапками, **один файл на страницу**:

```json
{
  "title": "guide.create.rotation",
  "route_step": "rotation",
  "quest": "repys:industry/first_rotation",
  "blocks": [
    { "type": "text", "text": "guide.create.rotation.intro" },
    { "type": "steps", "steps": [
      { "text": "guide.create.rotation.s1", "item": "create:water_wheel",
        "done": { "type": "item", "item": "create:water_wheel" } }
    ] },
    { "type": "structure", "source": "repys:guides/water_wheel", "layers": true, "show_in_world": true },
    { "type": "recipe", "item": "create:water_wheel" },
    { "type": "tip", "kind": "info", "text": "guide.create.rotation.tip" }
  ],
  "faq": [ { "q": "guide.create.rotation.q1", "a": "guide.create.rotation.a1" } ]
}
```

Прочитанность страниц хранится на сервере в ProgressStore (на игрока). «Понадобится» собирается автоматически из предметов шагов и блоков, автор может дополнить.

### Редактор страниц (dev-режим)

Та же оболочка редактора. Слева дерево гайда (разделы и страницы, перетаскивание), в центре страница списком блоков с ручками и вставкой «+ блок» (палитра типов, либо набор «/»), справа свойства блока, вкладки «Блок», «Страница», «Гайд», «JSON». Для структуры два источника: «Снять с мира» (отметить два угла) или файл `.nbt` из датапака. Внизу замечания: несуществующий квест, предмет, ключ lang.

Импорт книг Patchouli задуман кнопкой в редакторе. **Проверить перед кодом** (08-verify-first): реальный формат книг и страниц Patchouli и какие типы страниц есть у модов сборки; до проверки соответствие типов блокам не считать известным.

## Магазин (S4)

Сделка это отдельная сущность, не квест. Макет: `design/Shop.dc.html`.

```json
{
  "id": "repys:iron_bundle",
  "cost":  [ { "type": "currency", "id": "coin", "amount": 40 } ],
  "gives": [ { "type": "item", "id": "minecraft:iron_ingot", "count": 32 } ],
  "limit": { "per": "player", "count": 3, "reset": "daily" },
  "stage": "epoch_2"
}
```

- Валюта: число на сервере в ProgressStore, не предмет. Новый тип награды `currency` у квестов и достижений. Валют может быть несколько.
- Продажа: та же сделка, где `cost` это предметы, а `gives` это валюта.
- Кошельки: личный и казна команды (казна появляется вместе с RYSTeams).
- Лимиты на игрока или команду, сброс `never`, `daily`, `weekly`. История последних сделок.
- Сервер авторитетен: проверяет баланс, лимит, стадию и место в инвентаре.
- Dev-отчёт предупреждает, если цепочка сделок даёт положительный цикл (дюп через продажу и обратную покупку).

## Достижения (S5)

Те же типы задач, что у квеста, плюс уровни. Макет: `design/Achievements.dc.html`.

```json
{
  "id": "repys:factory_worker",
  "category": "tech",
  "task": { "type": "stat", "stat": "create:assembled" },
  "tiers": [
    { "tier": "bronze", "amount": 10,   "rewards": [ { "type": "currency", "id": "coin", "amount": 10 } ] },
    { "tier": "silver", "amount": 100,  "rewards": [ { "type": "title", "id": "factory_worker" } ] },
    { "tier": "gold",   "amount": 1000, "rewards": [ { "type": "currency", "id": "coin", "amount": 150 } ] }
  ],
  "hidden": false
}
```

- Счётчики копятся с первого входа. Скрытые показывают «???» и подсказку.
- Редкость по серверу считается на сервере и кэшируется.
- Сюжет не блокируют. Можно закрепить на HUD.
- Источник счётчика в примере условный: какие события реально дают моды, проверять для каждого типа задачи (см. 08-verify-first).

## Общие данные

`book.json` задаёт рейку:

```json
{ "sections": ["story", "guides", "repys:build_atlas", "repys:mining_atlas", "shop", "achievements"] }
```

Без `sections` книга работает как в MVP: один раздел `story`, рейка скрыта.

У главы поле `"section"`, по умолчанию `story`. **Это единственное, что закладывается в M1.**

## Порядок работ

| Этап | Что | Зависит от | Оценка |
|---|---|---|---|
| M1 (сейчас) | поле `section` у главы, фильтр `story` | — | полчаса |
| S1 | рейка разделов, Гайды: библиотека, страницы из блоков, маршрут, «Куда двигаться», редактор страниц | M3, M7 | 4–5 сессий |
| S2 | кастомные вкладки: шаблоны Матрица, Карточки, Страницы (блоки уже есть из S1), вид игрока | S1, стадии из M5 | 3 сессии |
| S3 | конструктор вкладок в dev-режиме | S2, редактор квестов | 2–3 сессии |
| S4 | Валюта и Магазин | M2 | 3 сессии |
| S5 | Достижения | S4 | 2 сессии |

После S2 вкладку уже можно собрать руками в JSON, конструктор (S3) это удобство поверх того же файла.

## Что было отброшено

Раньше здесь была «Карта руд»: высоты и биомы, прочитанные из генерации мира. Отброшено по решению автора: нужен не справочник высот, а **Атлас добычи** со способами по стадиям, и собирать его должен автор пака вручную. Старый макет `Ores.dc.html` перенесён в `_stale`. Автоматическое чтение worldgen не планируется.
