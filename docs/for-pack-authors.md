# RYSQuests для авторов сборок и их инструментов

Документ для автора сборки и для ИИ, который ведёт её код. Формат полей: `02-data-format.md`.

## Где лежит книга

Книга это файлы, редактировать можно любым инструментом. После правки: `/reload` или `/rysquests reload`.

| Что | Где |
|---|---|
| Книга в датапаке | `data/<ns>/rysquests/` |
| Книга из импорта FTB | `config/rysquests/import/` (пак подключается сам) |
| Соответствие id FTB → наши | `config/rysquests/import/ftbq-ids.json` |
| Переводы импорта | `config/rysquests/import/assets/<ns>/lang/` |
| Отчёт импорта | `config/rysquests/import/import-report.md` |

Важно про импорт: `/rysquests import ftbq` пересоздаёт `data/` и `assets/` внутри папки импорта. Правки, которые должны жить дальше, делайте в FTB и импортируйте заново либо перенесите книгу в свой датапак и больше не импортируйте. Чтобы id квеста не менялся, не удаляйте `ftbq-ids.json`.

Адаптация сборки, рекомендуемый порядок:

1. Выгрузить id пака: `/rysquests dev registry`, файл `logs/rysquests-registry.json`.
2. Импортировать: `/rysquests import ftbq repys`, затем `/rysquests import ftbq progress`.
3. Перенести `config/rysquests/import/data` и `assets` в датапак сборки или в Python-генератор и дальше менять там.
4. Проверять без игры: `tools/rysquests_check.py`.
5. Проверять в игре: `/reload`, затем `/rysquests dev report`.
6. Переименование квеста: запись `rename` в `migrations.json`, иначе прогресс игроков потеряется.

## Что происходит с FTB Quests

Импорт только читает `config/ftbquests/quests/` и `world/ftbquests/`. Файлы FTB Quests он не меняет, запись идёт только в `config/rysquests/import/`.

Это снимок, а не синхронизация:

- Выполненное в одном моде не появляется в другом. Правки в FTB попадут в книгу только при новом импорте.
- `/rysquests import ftbq progress` заменяет прогресс RYSQuests у команд из файлов FTB. Повторный запуск сотрёт то, что они успели сделать в RYSQuests после прошлого импорта.
- Пока включены оба мода, одну и ту же награду можно забрать дважды, в каждой книге. Перед выпуском сборки FTB Quests нужно убрать или закрыть его книгу. Заранее проверьте скрипты и моды, которые на него ссылаются.

## Как перестроить квесты под новый интерфейс

Порядок работы:

1. Импортировать книгу и прогресс (см. выше), взять id из `logs/rysquests-registry.json`.
2. Перенести `data/`, `assets/` и `pack.mcmeta` из `config/rysquests/import/` в датапак или генератор сборки. Старый пак автора не удалять, а переместить в `_stale`. Файл `ftbq-ids.json` оставить на месте: по нему импортируется прогресс. Если оставить `pack.mcmeta`, пак импорта продолжит подключаться и книг станет две (предупреждение `multiple_books`).
3. Не менять пространство имён и id квестов. Если переименование нужно, добавить запись `rename` в `migrations.json`.
4. Менять книгу по таблице ниже, проверять `tools/rysquests_check.py`, в игре `/reload` и `/rysquests dev report`.

Что где показывается:

| Поле | Где видно | Как заполнять |
|---|---|---|
| `chapter_order` | рейка глав и список глав | порядок задаёт номер главы |
| `title` главы | «V · Андезит» | римский номер интерфейс добавляет сам, поэтому «01. Андезит» надо заменить на «Андезит» |
| `section` главы | раздел книги | не заполнять: пока показываются только главы `story`, глава с другим значением пропадёт из книги |
| `epoch` главы | столбец в Ленте | главы с одним номером становятся одним столбцом с названием первой из них. Глава без `epoch` занимает отдельный столбец, поэтому гайды лучше собрать под одним номером |
| `default_view` главы | вид при открытии главы | `flow` для линейных глав, `map` для ветвистых |
| `title` квеста | узел карты, Поток, Список | в узле карты помещается примерно 17 символов, дальше многоточие |
| `icon` квеста | везде | заполнять всегда, без иконки в узле и строке будет пусто |
| `text` квеста | «Как сделать» и карточка у карты | только то, что помогает сделать квест. Служебные строки вроде «Необязательно. Середина. Награда: …» лучше убрать, награды показаны отдельно |
| `subtitle` квеста | только строка в Списке | коротко, в одну строку |
| `tasks` | строки задач | порядок важен: первая незакрытая задача на предмет определяет рецепт в превью |
| `title` задачи | вместо названия предмета | без количества, « ×16» интерфейс добавляет сам |
| `mode` задачи на предмет | кнопка «Сдать» | `consume` сдаётся кнопкой, `observe` засчитывается по наличию в инвентаре |
| `rewards` | строка награды, слоты | в Потоке видно до 4 слотов, названия предметов только при 1–2 наградах. `command` и `loot_table` не показываются: если игрок должен о них знать, напишите в `text` |
| `requires` | линии карты, «Дальше, на выбор», «Почему дальше закрыто» | |
| `stage_required` | причина закрытия квеста | стадию должна выдавать награда или продвижение, иначе квест попадёт в `unreachable` |
| `group` и `groups` главы | пунктирная рамка на карте, «По подглавам» в Списке | |
| `tags: ["milestone"]` | вехи в Ленте | до 3 на эпоху. Без тега берутся квесты, открывающие больше всего других |
| `tags: ["key_item"]` | ключевой предмет эпохи | один квест на эпоху, берётся его `icon`. Без тега используется последняя веха |
| `layout.x`, `layout.y` | узел на карте | обычно не нужны, раскладка автоматическая |

Важные особенности:

- Квест без задач засчитывается сам, как только откроется. Для страниц-гайдов добавьте задачу `rysquests:checkbox` с заголовком «Прочитано».
- Поля `page` и `size` читаются, но пока ни на что не влияют.
- Превью рецепта строится по рецептам Minecraft. Для машин, которые не сообщают результат, его не будет, ссылка `[[item:…]]` при этом работает.
- Текст поддерживает ссылки `[[item:id|подпись]]`, `[[quest:id|подпись]]`, `**жирный**`, `!!предупреждение!!`, `>>спойлер<<` и цветовые коды `§`.
- Доска стикеров стоит справа сверху. Если там миникарта, поднимите `boardTop` в `config/rysquests-client.toml`.

## Команды

Уровень прав 2, кроме `team`.

| Команда | Что делает | Результат |
|---|---|---|
| `/rysquests reload` | штатная перезагрузка датапаков | чат |
| `/rysquests validate` | проверка книги и тегов | чат, `logs/rysquests-validate.txt` |
| `/rysquests dev report` | полный отчёт для инструментов | `logs/rysquests-report.json`, `.csv` |
| `/rysquests dev registry` | все id пака | `logs/rysquests-registry.json` |
| `/rysquests import ftbq [ns]` | книга из FTB Quests, по умолчанию `ns` = `ftbq` | `config/rysquests/import/` |
| `/rysquests import ftbq progress` | прогресс из `world/ftbquests/` | чат |
| `/rysquests migrate --dry-run` | что изменят миграции | чат, `logs/rysquests-migrate.txt` |
| `/rysquests migrate --apply` | применить, сначала бэкап | бэкап в `world/data/` |
| `/rysquests progress <игрок> reset\|complete <квест>` | правка прогресса | |
| `/rysquests team create\|invite <игрок>\|join\|leave` | команды игроков | |

Новые миграции применяются сами при старте мира и после `/reload`.

## Проверка без игры

Нужен только Python 3:

```
python tools/rysquests_check.py <корень пака> --registry logs/rysquests-registry.json --lang ru_ru
python tools/rysquests_check.py <корень пака> --registry logs/rysquests-registry.json --json
```

`<корень пака>` содержит `data/<ns>/rysquests/`. Проверяет: JSON, обязательные поля, повторы id, отсутствующие зависимости и главы, циклы, типы задач и наград, предметы, теги, существ, продвижения, переводы. Код выхода 1, если есть ошибки. `--json` печатает результат для других программ: `{chapters, quests, errors, warnings, issues: [{severity, code, subject, detail}]}`.

Без `--registry` id предметов не проверяются.

## Отчёт `rysquests-report.json`

```json
{ "chapters": 54, "quests": 2381,
  "sections": [ { "id": "errors", "entries": [ { "subject": "repys:a/b", "detail": "missing_dependency: repys:a/c" } ] } ] }
```

Секции: `errors`, `warnings`, `unreachable` (квест нельзя открыть: зависимостей меньше, чем нужно, или стадию ничто не выдаёт), `no_recipe` (предмет задачи без известного рецепта). Рецепты машин некоторых модов сюда не попадают как результат, поэтому `no_recipe` это кандидаты, а не приговор.

Коды ошибок: `parse_error`, `duplicate_quest`, `duplicate_chapter`, `unknown_chapter`, `missing_dependency`, `dependency_cycle`, `unknown_item`, `empty_reward`; предупреждения: `broken_dependency`, `unknown_group`, `unknown_chapter_dependency`, `unknown_chapter_order`, `multiple_books`, `empty_tag`.

Сломанный квест не валит книгу: он выпадает вместе с зависимыми, остальное загружается.

## Из кода мода и скриптов

- `works.repka.rysquests.api.QuestsApi`: книга, отметка квеста, регистрация стадий.
- `QuestCompletedEvent` на игровой шине NeoForge.
- Свои типы задач и наград: реестры `rysquests:task_type` и `rysquests:reward_type`.
- Из KubeJS: `RYSQuestsEvents.completed`, `task` и `reward` в серверных скриптах, задача и награда `rysquests:script`, примеры в `03-api.md`.
- Команда как награда: `{ "type": "rysquests:command", "command": "ryscope stage grant @s config:iron_age", "as_server": true }`.

Рецепт для ссылки в тексте: `[[item:minecraft:stone]]`, `[[quest:repys:a/b|подпись]]`, полный синтаксис в `02-data-format.md`.
