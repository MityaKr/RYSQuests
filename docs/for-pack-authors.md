# RYSQuests для авторов сборок и их инструментов

Документ для автора сборки и для ИИ, который ведёт её код. Все возможности с примерами: `GUIDE.md`. Формат полей: `02-data-format.md`. Готовый промпт для ИИ сборки: `PROMPT-modpack-ai.md`.

## Где лежит книга

Книга это файлы, редактировать можно любым инструментом. После правки: `/reload` или `/rysquests reload`.

| Что | Где |
|---|---|
| Книга в датапаке | `data/<ns>/rysquests/` |
| Книга из импорта FTB | `config/rysquests/import/` (пак подключается сам) |
| Соответствие id FTB → наши | `config/rysquests/import/ftbq-ids.json` |
| Переводы импорта | `config/rysquests/import/assets/<ns>/lang/` |
| Отчёт импорта | `config/rysquests/import/import-report.md` |

Важно про импорт: `/rysquests import ftbq` пересоздаёт `data/` и `assets/` внутри папки импорта. Правки, которые должны жить дальше, делайте в FTB и импортируйте заново либо перенесите книгу в свой датапак и больше не импортируйте. Чтобы id квеста не менялся, не удаляйте `ftbq-ids.json`.

Адаптация сборки, рекомендуемый порядок:

1. Выгрузить id пака: `/rysquests dev registry`, файл `logs/rysquests-registry.json`.
2. Импортировать: `/rysquests import ftbq repys`, затем `/rysquests import ftbq progress`.
3. Перенести `config/rysquests/import/data` и `assets` в датапак сборки или в Python-генератор и дальше менять там.
4. Проверять без игры: `tools/rysquests_check.py`.
5. Проверять в игре: `/reload`, затем `/rysquests dev report`.
6. Переименование квеста: запись `rename` в `migrations.json`, иначе прогресс игроков потеряется.

## Что происходит с FTB Quests

Импорт только читает `config/ftbquests/quests/` и `world/ftbquests/`. Файлы FTB Quests он не меняет, запись идёт только в `config/rysquests/import/`.

Это снимок, а не синхронизация:

- Выполненное в одном моде не появляется в другом. Правки в FTB попадут в книгу только при новом импорте.
- `/rysquests import ftbq progress` заменяет прогресс RYSQuests у команд из файлов FTB. Повторный запуск сотрёт то, что они успели сделать в RYSQuests после прошлого импорта.
- Пока включены оба мода, одну и ту же награду можно забрать дважды, в каждой книге. Перед выпуском сборки FTB Quests нужно убрать или закрыть его книгу. Заранее проверьте скрипты и моды, которые на него ссылаются.

## Как перестроить квесты под новый интерфейс

Порядок работы:

1. Импортировать книгу и прогресс (см. выше), взять id из `logs/rysquests-registry.json`.
2. Перенести `data/`, `assets/` и `pack.mcmeta` из `config/rysquests/import/` в датапак или генератор сборки. Старый пак автора не удалять, а переместить в `_stale`. Файл `ftbq-ids.json` оставить на месте: по нему импортируется прогресс. Если оставить `pack.mcmeta`, пак импорта продолжит подключаться и книг станет две (предупреждение `multiple_books`).
3. Не менять пространство имён и id квестов. Если переименование нужно, добавить запись `rename` в `migrations.json`.
4. Менять книгу по таблице ниже, проверять `tools/rysquests_check.py`, в игре `/reload` и `/rysquests dev report`.

Что где показывается:

| Поле | Где видно | Как заполнять |
|---|---|---|
| `chapter_order` | рейка глав и список глав | порядок задаёт номер главы |
| `title` главы | «V · Андезит» | римский номер интерфейс добавляет сам, поэтому «01. Андезит» надо заменить на «Андезит» |
| `section` главы | раздел книги | не заполнять: пока показываются только главы `story`, глава с другим значением пропадёт из книги |
| `epoch` главы | столбец в Ленте | главы с одним номером становятся одним столбцом с названием первой из них. Глава без `epoch` занимает отдельный столбец, поэтому гайды лучше собрать под одним номером |
| `default_view` главы | вид при открытии главы | `flow` для линейных глав, `map` для ветвистых |
| `title` квеста | узел карты, Поток, Список | в узле карты помещается примерно 17 символов, дальше многоточие |
| `icon` квеста | везде | заполнять всегда, без иконки в узле и строке будет пусто |
| `text` квеста | «Как сделать» и карточка у карты | только то, что помогает сделать квест. Служебные строки вроде «Необязательно. Середина. Награда: …» лучше убрать, награды показаны отдельно |
| `subtitle` квеста | только строка в Списке | коротко, в одну строку |
| `tasks` | строки задач | порядок важен: первая незакрытая задача на предмет определяет рецепт в превью |
| `title` задачи | вместо названия предмета | без количества, « ×16» интерфейс добавляет сам |
| `mode` задачи на предмет | кнопка «Сдать» | `consume` сдаётся кнопкой, `observe` засчитывается по наличию в инвентаре |
| `rewards` | строка награды, слоты | в Потоке видно до 4 слотов, названия предметов только при 1–2 наградах. `command` и `loot_table` не показываются: если игрок должен о них знать, напишите в `text` |
| `requires` | линии карты, «Дальше, на выбор», «Почему дальше закрыто» | |
| `stage_required` | причина закрытия квеста | стадию должна выдавать награда или продвижение, иначе квест попадёт в `unreachable` |
| `group` и `groups` главы | пунктирная рамка на карте, «По подглавам» в Списке | |
| `tags: ["milestone"]` | вехи в Ленте | до 3 на эпоху. Без тега берутся квесты, открывающие больше всего других |
| `tags: ["key_item"]` | ключевой предмет эпохи | один квест на эпоху, берётся его `icon`. Без тега используется последняя веха |
| `layout.x`, `layout.y` | узел на карте | обычно не нужны, раскладка автоматическая: главный путь из квестов без подглавы по центру, подглавы блоками выше и ниже него (ADR-44) |

Важные особенности:

- Квест без задач засчитывается сам, как только откроется. Для страниц-гайдов добавьте задачу `rysquests:checkbox` с заголовком «Прочитано».
- Поля `page` и `size` читаются, но пока ни на что не влияют.
- Рецепт машины, который книга не может прочитать сама, рисует JEI. Без JEI его не будет, ссылка `[[item:…]]` при этом работает.
- Текст поддерживает ссылки `[[item:id|подпись]]`, `[[quest:id|подпись]]`, `**жирный**`, `!!предупреждение!!`, `>>спойлер<<` и цветовые коды `§`.
- Угол доски стикеров общий для семьи RYS и задаётся в настройках RYSCore, зону миникарты она обходит сама.

### Награда эпохи на карте (0.2.7)

Квест, который выдаёт награду за эпоху, можно убрать из главы и показать на самой эпохе. В `book.json` эпоха пишется объектом и называет свой квест:

```json
"epochs": [
  { "title": "book.repys.epoch.1", "quest": "repys:a01_map/i_mechanics" },
  { "title": "book.repys.epoch.2", "quest": "repys:a01_map/ii_industry" }
]
```

- Квест остаётся в своём файле и главе, id не меняется, миграции не нужны. Кто уже забрал награду в главе, второй раз её не получит; кто не забрал, заберёт на карте.
- Карточкой главы такой квест больше не показывается: ни на карте, ни в списке, ни в поиске, ни в счёте главы. Глава, где кроме наград эпох ничего нет, уходит из сайдбара.
- Игрок видит значок награды на плашке эпохи и в строке эпохи сайдбара, клик по плашке открывает карточку: текст квеста (лор эпохи и ветки), награды, выбор и «Забрать награду». Награда ждёт и на «Сейчас».
- Награда открывается, когда выполнены зависимости квеста (обычно ключевой квест прошлой эпохи), а из задач осталась только галочка: её мод ставит сам при получении. Задача другого вида держит эпоху закрытой.
- Награды «каждому» и «одна на команду» работают как у любого квеста: уход из команды, возвращение и слияние команд ничего не выдают дважды.

### Страницы «О книге» (0.2.7)

Поле `"about"` в `book.json` делает название книги в шапке кнопкой: она открывает страницы поверх вкладки, как настройки. Можно назвать гайд книги, тогда ссылки на него и отметки прочитанного сохраняются, а гайд остаётся и в библиотеке:

```json
"about": "repys:book"
```

Или написать страницы прямо в `book.json` в формате страниц гайда (тексты ключами lang):

```json
"about": [
  { "id": "welcome", "title": "book.repys.about.welcome", "text": "book.repys.about.welcome.text" },
  { "id": "coins", "title": "book.repys.about.coins", "text": "book.repys.about.coins.text" }
]
```

Пока игрок не открыл ни одной страницы, у названия горит точка. Блок «Гайд для начала» на «Сейчас» берёт эти страницы. Страницы рисуются тем же экраном, что гайды: работают вставки, рецепты, картинки и ссылки.

## Гайды

Гайд это файл `data/<ns>/rysquests/guides/<id>.json`: название, иконка, необязательные категория и стадия, список страниц. Тексты в lang. Формат и вставки в `02-data-format.md` и `09-sections.md`, живой пример в `examples/example_pack`.

Чтобы гайды появились в книге, добавь в `book.json` строку `"sections": ["story", "guides"]`. Без неё рейки разделов нет и книга выглядит как раньше.

Вставки в тексте страницы: `[[item:id]]`, `[[recipe:id]]` и `[[image:ns:textures/guides/файл.png|подпись]]` (рецепт и картинка одни в строке становятся блоком), `[[quest:id]]`, `[[guide:id#страница]]`, `**жирный**`.

Поле `"guide": "ns:id#страница"` у квеста даёт кнопку «Как это работает». Панель справа собирается сама: квесты с этим полем, упомянутые в тексте и те, что просят предметы страницы, а также все предметы из текста.

Сервер проверяет ссылки квестов на гайды (`/rysquests validate`). Ключи lang, картинки и ссылки внутри текста видны только клиенту, они перечислены во вкладке Dev, раздел «Гайды: ключи, ссылки, файлы».

## Кастомные вкладки

Вкладка это файл `data/<ns>/rysquests/sections/<id>.json` с полем `template`: `matrix` (строки на столбцы, столбец можно привязать к стадии), `cards` (каталог с фильтрами и условием отметки), `pages` (страницы как у гайдов). Чтобы вкладка появилась на рейке, добавь её id в `sections` файла `book.json`. Формат в `09-sections.md`, рабочие примеры всех трёх в `examples/example_pack`.

С 0.2.7 игроки видят и матрицы (в RepYS это «Атлас сборки» и «Атлас добычи»), внутри «Гайды», как остальные вкладки автора (ADR-60). Раньше их видел только оператор. Править вкладки по-прежнему может только оператор. Чтобы спрятать вкладку от игроков, не пиши её id в `sections`.

Файл можно править руками: после `/rysquests reload` изменения сразу в книге.

## Редактор в игре

Оператор (уровень 2) может создать гайд кнопкой «+» в библиотеке и править гайд или вкладку «Страницы» значком карандаша. Работает в одиночной игре и на выделенном сервере.

Файлы пишет сервер в папку из настройки `editorFolder` файла `config/rysquests-common.toml`, по умолчанию `config/rysquests/pack`. Если книга сборки лежит в KubeJS, укажи `kubejs`. Папка устроена как пак: `data/<ns>/rysquests/guides/`, `assets/<ns>/lang/`, `assets/<ns>/textures/guides/`. Сохранённое сразу видно всем игрокам: переводы и картинки из этой папки идут вместе с книгой. В релиз папка попадает как обычные файлы сборки.

Конструктор вкладок открывается кнопкой на вкладке Dev или карандашом на самой вкладке. В нём меняется порядок рейки, создаются вкладки из шаблонов, правятся таблица Матрицы и Карточки.

Редактор квестов открывается кнопкой на вкладке Dev: глава на карте, создание квестов, зависимости перетаскиванием, задачи и награды, автораскладка. Подробно в `GUIDE.md`, раздел 15.

## Магазин

Сделка это файл `data/<ns>/rysquests/shop/<id>.json`, формат в `02-data-format.md`, примеры в `examples/example_pack`. Раздел включается строкой `shop` в `sections`. Монеты дают квесты наградой `rysquests:currency`, для проверки есть команда `/rysquests wallet add <игрок> <валюта> <сумма>`. Отчёт `shop_cycles` на вкладке Dev показывает цепочки сделок, которые печатают деньги. Все поля ниже правятся и в редакторе книги, вкладка «Магазин» (с 0.2.7).

### Схема или предмет с данными, один раз на команду

`components` у предмета в `gives` выдаются как есть (схема Create с файлом, зачарование, имя), лимит `{ "per": "team", "count": 1 }` даёт покупку один раз на команду. Переходы между командами второй копии не дают. В редакторе компоненты берутся с предмета в руке или пишутся JSON в поле под строкой.

### Трофей босса

1. Нужно достижение с задачей `rysquests:kill` и одной сущностью, первый уровень с `amount: 1` (у RepYS это `achievements/slayer_<босс>.json`, уровень `gold`).
2. В сделке `quest` указывает на этот уровень: `"quest": "repys:_achievements/slayer_ignis/gold"`. В редакторе: «Открывается: После победы» и босс из списка.
3. Первое убийство кем-то из команды открывает сделку всей команде навсегда. Засчитывается только удар настоящего игрока, дробилки и раздатчики не считаются.
4. Закрытая карточка сама пишет «победи: Игнис». Своя строка: `lock_text`, ключ перевода или текст (в редакторе поле «Строка закрытой карточки»). `lock_text` работает у любой закрытой сделки: по квесту, по этапу, по боссу.

Если сделка ещё и в поздней эпохе (`stage`), до открытия эпохи карточка называет эпоху, потом босса.

### Поставка (накопительная сделка)

`"delivery": true`: предметы из `cost` команда сдаёт частями в общий счёт, валюта из `cost` списывается при выдаче. Нужен хотя бы один предмет в `cost`, продажа поставкой быть не может (иначе ошибки `offer_delivery_items`, `offer_delivery_sale`, сделка выпадает из книги). Количества могут быть любыми, хоть тысячи: сдают кнопкой «Сдать из инвентаря» или блоком «Приёмщик». Строки с одним предметом складываются. Лимит сделки, если задан, считает выдачи. Сбросить счёт: `/rysquests shop delivery reset <игроки> [сделка]`.

В редакторе: переключатель «Поставка» (первая строка берётся из предмета в руке), строки «Сдать поставкой» с полем числа. Трофей с поставкой это обе вещи вместе: `quest` на уровень босса и `delivery: true`.

### Блоки «Приёмщик» и «Выдача»

С 0.2.7 у блоков есть рецепты по умолчанию из ванильных предметов, верстак, shaped:

| Рецепт (id) | Сетка | Ключ |
|---|---|---|
| `rysquests:shop_receiver` | `IEI` / `IHI` / `ICI` | I `#c:ingots/iron`, E `#c:gems/emerald`, H `minecraft:hopper`, C `#c:chests/wooden` без `#c:chests/trapped` |
| `rysquests:shop_dispenser` | `IEI` / `IDI` / `IRI` | I `#c:ingots/iron`, E `#c:gems/emerald`, D `minecraft:dispenser`, R `#c:dusts/redstone` |

Файлы `data/rysquests/recipe/shop_receiver.json` и `shop_dispenser.json`. Рецепт открывается в книге рецептов, когда в инвентаре появляется воронка или раздатчик (`data/rysquests/advancement/recipes/redstone/*.json`). Сборка заменяет рецепт по id, например KubeJS:

```js
ServerEvents.recipes(event => {
  event.remove({ id: 'rysquests:shop_receiver' })
  event.remove({ id: 'rysquests:shop_dispenser' })
  event.shaped('rysquests:shop_receiver', ['SBS', 'BHB', 'SBS'], { S: '#c:ingots/steel', B: 'create:brass_casing', H: 'minecraft:hopper' })
  event.shaped('rysquests:shop_dispenser', ['SBS', 'BDB', 'SBS'], { S: '#c:ingots/steel', B: 'create:brass_casing', D: 'minecraft:dropper' })
})
```

Можно и датапаком: файл с тем же путём `data/rysquests/recipe/<id>.json` в датапаке сборки перекрывает рецепт мода. Без рецепта блоки берут в творческом режиме (вкладка «Функциональные блоки») или `/give @s rysquests:shop_receiver`.

- «Приёмщик» (`rysquests:shop_receiver`) продаёт всё, что в него приходит, по выбранной в окне продаже, или сдаёт поступившее в поставку команды. Предметы принимает с любой стороны через `Capabilities.ItemHandler.BLOCK`, только на вставку: трубы, воронки Create, хоппер, шина экспорта AE2. Берёт только предметы сделки, простые и только недостающие, чужое остаётся в трубе. Монеты в свой кошелёк или в казну команды.
- «Выдача» (`rysquests:shop_dispenser`) покупает выбранную сделку (цена только монеты, выдаются предметы) раз в секунду и кладёт товар в инвентарь с выбранной стороны или в свой слот, откуда его забирают трубы (только извлечение). Ограничения «потратить не больше» (с последнего сброса счётчика), «оставить на счету» и «держать в инвентаре не больше», выключатель «только при сигнале редстоуна». Платить из казны можно с правом `spend_treasury`.
- Окно открывают владелец (кто поставил) и его команда, ломают они же и оператор. Сделка с `stage` блоку доступна, только пока владелец в игре. У обоих блоков компаратор (по состоянию или по заполненности) и уведомление владельцу, когда блок встал, не чаще раза в минуту.
- Что смотреть при балансе: «Приёмщик» снимает потолок с продаж (магазин не должен печатать деньги, проверяй отчёт `shop_cycles` и свои круги через рецепты), «Выдача» превращает монеты в поток сырья.

## Достижения

Достижение это файл `data/<ns>/rysquests/achievements/<id>.json` с задачей и уровнями, формат в `02-data-format.md`, примеры в `examples/example_pack`. Раздел включается строкой `achievements` в `sections`. Подходят задачи `kill`, `stat`, `item`, `advancement` и `collection`. Награды выдаются сами, тип `rysquests:title` даёт титул перед именем.

### Коллекция (0.2.8)

Если достижение просит собрать набор предметов, задача `rysquests:collection` со списком `items`, а `amount` уровней это число собранных. Игрок видит в окне достижений каждый предмет: собран он или нет, подсказку предмета и «нужно 64 сразу» для набора штук; карточка пишет «5 из 8», закреплённый уровень на HUD рисует полоску. В команде предмет засчитан, если побывал у кого-то из неё, держать все сразу не нужно. Счётчик скриптом (`rysquests:script` плюс своё хранилище) больше не нужен.

Переход со скрипта без потери отметок: оставить старое хранилище, сменить задачу достижения на `collection` и один раз пройти по отметкам скрипта вызовом `RYSQuests.collect(server, owner, achievement, item)` (KubeJS, серверный скрипт). Повтор безопасен, поэтому скрипт переноса можно оставить на одну-две версии. Пример переноса для хранилища вида `server.persistentData.<ключ>.<команда>.<коллекция>|<предмет>` лежит в ADR-62 (`07-decisions.md`).

Окно достижений: кнопка булавки серая, когда на HUD уже закреплено `hud.max_pinned` карточек (по умолчанию 3), подсказка объясняет, что открепить. У закреплённого достижения булавка видна на карточке.

## Предварительное выполнение (0.2.10)

Если включено, задачи закрытого квеста засчитываются заранее: игрок может собрать предмет, убить моба, дойти до места до того, как квест откроется. Квест остаётся закрытым, в его панели написано «Условие уже выполнено», а когда открывается, сразу засчитывается, и награда ждёт «Забрать». Предметы на сдачу у закрытого квеста не забираются, их сдают после открытия. Включается полем `"pre_complete": true` в `book.json` (для всей книги), в `_chapter.json` (для главы) или в файле квеста; `false` выключает, без поля берётся значение уровнем выше (квест, глава, книга, по умолчанию выключено). В редакторе: «Предварительное выполнение» в форме главы и в «Ещё» у квеста, там же в форме главы «Во всей книге». Импорт из FTB Quests переносит `progression_mode` (`flexible` это включено).

## Цели квестов на карте (0.2.9)

С RYSMap у карты есть слой «Цели квестов». Метку получает квест, у которого есть задача `rysquests:visit` с координатами: `"pos": [x, y, z]`, при надобности `"dimension"` (без него верхний мир) и `"radius"` (по умолчанию 8, это и круг района на карте) или `"size": [dx, dy, dz]` для коробки. Задача только с измерением, биомом или структурой места не имеет, метки не будет. Метка видна, пока квест открыт и место не посещено; клик открывает панель с кнопками «Открыть квест» и «Сохранить точкой», поиск карты находит квест по имени. Подпись в мире появляется, только когда игрок закрепил квест. В книге у такой задачи кнопка «На карте».

## Монеты из скриптов (KubeJS)

В серверных скриптах есть объект `RYSQuestsWallet`. Методы, и все принимают игрока первым:

| Метод | Что делает |
|---|---|
| `balance(player, currency)` | баланс игрока |
| `treasury(player, currency)` | баланс казны команды, `0` без команды |
| `deposit(player, currency, amount)` | зачислить игроку |
| `depositTreasury(player, currency, amount)` | зачислить в казну, `false` без команды |
| `withdraw(player, currency, amount)` | списать, `false` и без списания, если не хватает |
| `exchange(player, item, currency, items, coins)` | обменять предметы со всего инвентаря, кроме брони |
| `exchangeHeld(player, item, currency, items, coins)` | то же только из главной руки |

`item` это id предмета или тег `#c:coins`. За каждые `items` предметов игрок получает `coins` монет, остаток меньше одной партии остаётся у него, метод возвращает зачисленные монеты. Обмен идёт на сервере и попадает в историю магазина как «обмен». Валюта это та же строка, что в сделках и награде `rysquests:currency`.

Готовый блок-обменник: `examples/kubejs/server_scripts/rysquests_coin_exchange.js`. Скопируй файл в `kubejs/server_scripts`, поменяй `EXCHANGER`, `CURRENCY` и таблицу `RATES`, выполни `/reload`. Блок может быть любым, в том числе созданным в KubeJS.

## Проверка без игры

Нужен только Python 3:

```
python tools/rysquests_check.py <корень пака> --registry logs/rysquests-registry.json --lang ru_ru
python tools/rysquests_check.py <корень пака> --registry logs/rysquests-registry.json --json
```

`<корень пака>` содержит `data/<ns>/rysquests/`. Проверяет: JSON, обязательные поля, повторы id, отсутствующие зависимости и главы, циклы, типы задач и наград, предметы, теги, существ, продвижения, переводы. Код выхода 1, если есть ошибки. `--json` печатает результат для других программ: `{chapters, quests, errors, warnings, issues: [{severity, code, subject, detail}]}`.

Без `--registry` id предметов не проверяются.

## Отчёт `rysquests-report.json`

```json
{ "chapters": 54, "quests": 2381,
  "sections": [ { "id": "errors", "entries": [ { "subject": "repys:a/b", "detail": "missing_dependency: repys:a/c" } ] } ] }
```

Секции: `errors`, `warnings`, `unreachable` (квест нельзя открыть: зависимостей меньше, чем нужно, или стадию ничто не выдаёт), `no_recipe` (предмет задачи без известного рецепта). Рецепты машин некоторых модов сюда не попадают как результат, поэтому `no_recipe` это кандидаты, а не приговор.

Коды ошибок: `parse_error`, `duplicate_quest`, `duplicate_chapter`, `unknown_chapter`, `missing_dependency`, `dependency_cycle`, `unknown_item`, `empty_reward`; предупреждения: `broken_dependency`, `unknown_group`, `unknown_chapter_dependency`, `unknown_chapter_order`, `multiple_books`, `empty_tag`.

Сломанный квест не валит книгу: он выпадает вместе с зависимыми, остальное загружается.

## Из кода мода и скриптов

- `works.repka.rysquests.api.QuestsApi` (в KubeJS `RYSQuests`): книга, отметка квеста, регистрация стадий, владелец прогресса и отметка предмета коллекции (`collect`, 0.2.8), чтение прогресса `isCompleted(owner, quest)` и `completed(owner)` (0.2.9).
- `QuestCompletedEvent` на игровой шине NeoForge.
- Свои типы задач и наград: реестры `rysquests:task_type` и `rysquests:reward_type`.
- Из KubeJS: `RYSQuestsEvents.completed`, `task` и `reward` в серверных скриптах, задача и награда `rysquests:script`, примеры в `03-api.md`.
- Команда как награда: `{ "type": "rysquests:command", "command": "ryscope stage grant @s config:iron_age", "as_server": true }`.

Рецепт для ссылки в тексте: `[[item:minecraft:stone]]`, `[[quest:repys:a/b|подпись]]`, полный синтаксис в `02-data-format.md`.
