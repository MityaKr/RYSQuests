# RYSQuests — правила работы в репозитории

## Общение
- С автором общаться только по-русски. Код, идентификаторы, комментарии в коде, сообщения коммитов и тексты для игроков (lang en_us) на английском; lang ru_ru на русском.
- Прогресс показывать списком сверху: сделанное помечать ✅, без зачёркиваний. Перед началом этапа коротко излагать план этапа. Законченный шаг показывать сразу и продолжать.
- Если не уверен в API NeoForge или Minecraft, не выдумывать: открыть исходники (ModDevGradle подключает декомпилированные исходники Minecraft и NeoForge) или декомпилировать мод через CFR, и только потом писать. При сомнении сказать «проверю» и проверить.
- Перед любым текстом, который увидят игроки (lang, чейнджлог), показать черновик автору.

## Файлы и среда
- Ничего не удалять: `rm`, `git rm`, `git clean` запрещены. Ненужное переносить в `_stale/` (в `.gitignore`).
- Не делать `git commit` и `git push` без явной просьбы автора. Коммит после каждого принятого этапа, по просьбе.
- Тесты в игре только в отдельном новом мире инстанса `run/`, никогда в мирах автора. Тестовый мир не удалять, переиспользовать.
- Maven NeoForge может быть недоступен из этой среды. Перед M0 проверить `https://maven.neoforged.net/releases`. Если недоступен, остановиться и обсудить с автором (оффлайн-кэш Gradle, зеркало), не изобретать обходы молча.
- Версии зависимостей фиксировать в `gradle.properties`, не в коде сборки.

## Код
- Java 21, NeoForge 21.1.x, Minecraft 1.21.1. Mojang mappings (официальные), как даёт ModDevGradle.
- Пакеты: `works.repka.rysquests` (мод) и `works.repka.ryscore` (UI-библиотека, без зависимостей на rysquests; выделяется позже). Из `rysquests` можно зависеть от `ryscore`, обратно нельзя.
- Клиентский код только в пакете `...client` и только за `Dist.CLIENT` / `@EventBusSubscriber(value = Dist.CLIENT)`. Сервер никогда не импортирует `net.minecraft.client`.
- Сериализация через `Codec` (данные) и `StreamCodec` (сеть). Без ручного парсинга JSON.
- Строковые id везде: `ResourceLocation` для квестов, глав, типов задач. Никаких числовых id.
- Ничего тяжёлого в главном потоке: раскладка графа, отчёты валидации, миграции считаются вне тика (`Util.backgroundExecutor()` или свой executor), результат применяется в тике.
- Прогресс синхронизируется диффами, не целиком. Книга отправляется целиком только при входе и при `/reload`.
- Один файл на квест в датапаке; редактор пишет те же файлы. Порядок полей в JSON стабилен (использовать упорядоченный вывод).
- Логи через `org.slf4j.Logger`, уровень INFO только для событий жизненного цикла, остальное DEBUG.
- Тесты: JUnit 5 для кодеков, графа, раскладки, миграций, импортёра. Перед сдачей этапа тесты зелёные и `runClient` запускается без ошибок в логе.

## Процесс
- Работать строго по `docs/05-plan.md`: один этап за раз, критерии приёмки проверяются перед переходом.
- Любое отклонение от `docs/07-decisions.md` оформлять новой записью ADR и согласовывать с автором.
- Изменения формата данных сопровождать записью в `docs/02-data-format.md` и, если ломается старый формат, миграцией.
- Не добавлять функции из будущих этапов «заодно».
